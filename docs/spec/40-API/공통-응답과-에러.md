## 1. 성공 응답 형식

### 1.1 봉투를 쓰지 않는다

51개 엔드포인트 전부가 **평면 dict 를 그대로 반환**합니다. `{"data": ..., "meta": ...}`
같은 봉투가 없습니다.

```json
// POST /api/quant/portfolio-scenario 응답 (app/backend/routers/quant.py:93~104)
{
  "profile_label": "균형 중심",
  "years": 10,
  "total_paid": 70000000,
  "points": [{ "year": 0, "cautious": 10000000, "middle": 10000000, "positive": 10000000 }],
  "summary": { "cautious": 0, "middle": 0, "positive": 0 },
  "explanation": "..."
}
```

**v2.0 에서도 봉투를 도입하지 않습니다.** 51개를 전부 고치는 비용이 크고, 프런트
40개 호출부가 전부 평면을 전제로 짜여 있습니다. 신설 API 도 평면을 따릅니다
([API-상세명세 2.2절](API-상세명세.md#22-신설-4개-요약)).

### 1.2 공통 규칙

| 규칙 | 실측 근거 |
| --- | --- |
| 키는 **snake_case** | `period_label`(`main.py:1233`) · `chart_points`(`main.py:1242`) · `profile_label`(`quant.py:94`) |
| 시각은 **ISO 8601 문자열** | `latest_data_at`(`main.py:1227`) · `fetched_at`(`main.py:222`) |
| 날짜만 필요하면 `YYYY-MM-DD` | `chart_points[].date`(`main.py:1228`) |
| **한국어 설명 문장을 응답에 포함** | `summary`·`portfolio_hint`(`main.py:1215`) · `explanation`(`quant.py:105`) |
| 라벨은 **서버가 완성해서** 보낸다 | `period_labels`(`main.py:1222`) · `profiles[*].label`(`quant.py:67~69`) |
| 시계열은 **작은 dict 의 배열** | `chart_points[{date,a,b}]` · `points[{year,cautious,middle,positive}]` |
| 차트는 base64 문자열 (**v2.1 에서 폐지**) | `"data:image/png;base64,..."`(`main.py:738`) 또는 순수 base64(`ml.py:210`) |

> (`main.py:1525,1788,1949` 는 `img_b64 = …` 대입문이고, 그 값이 실린 응답 키는
> `main.py:1540,1791,1956` 에서 전부 `"image"` 입니다).

| 필드명 | 접두사 | 위치 | 개수 |

| `image` | `data:image/png;base64,` **있음** | `main.py:742,856,1087,1540,1791,1956` · `quant.py:224,316,528,595,708` | **11** |
| `image_base64` | **없음** (순수 base64) | `ml.py:210,317,373,424,478` | **5** |

### 1.3 직렬화

## 2. 에러 응답 형식

### 2.1 현재 — 세 가지 형태

커스텀 핸들러가 없으므로 전부 FastAPI·Starlette 기본형입니다.

| 발생원 | HTTP | 본문 |
| --- | --- | --- |
| `raise HTTPException(status_code=N, detail="문장")` | N | `{"detail": "문장"}` — **문자열** |
| Pydantic 검증 실패 | 422 | `{"detail": [ {...}, ... ]}` — **배열** |
| 핸들러 밖 예외 | 500 | **JSON 이 아님.** `Internal Server Error` 텍스트 |

**422 본문 구조** (FastAPI `RequestValidationError` 기본형):

```json
{"detail": [{"type": "missing", "loc": ["body", "ticker_a"], "msg": "Field required", "input": {}}]}
```

> **(확인 필요)** 정확한 키 구성은 FastAPI·Pydantic 버전에 따라 다릅니다.
> `requirements.txt:1` 이 `fastapi` 로 **버전 핀이 없고** `Dockerfile:11~15` 도
> 최신본을 받으므로 저장소만으로 특정할 수 없습니다.
> 출처: [FastAPI Handling Errors](https://fastapi.tiangolo.com/tutorial/handling-errors/#requestvalidationerror-vs-validationerror) (2026-08-09 확인)

### 2.2 `HTTPException` 사용 실태

총 **49곳**입니다 (AST 전수 집계, 2026-08-09).

| 호출 스타일 | 개수 | 파일 |
| --- | --- | --- |
| `status_code=` 키워드 | 36 | `main.py` 24 · `ml.py` 6 · `backtest_lab.py` 3 · `tax.py` 3 |
| 위치인자 `HTTPException(503, "...")` | 13 | `rag.py` 7 · `backtest_lab.py` 6 |
| **없음** | 0 | `quant.py` — `HTTPException` 을 **import 조차 하지 않음** (`quant.py:9`) |

파일 단위로는 대체로 일관되지만 **`backtest_lab.py` 만 한 파일 안에서 3:6 으로 섞여
있습니다.** 같은 함수 묶음 안에서도 갈립니다 — `_check_period` 는 `:118,120,122,128` 이
전부 위치인자인데, 바로 위 `_require_core`(`:100`)와 아래 `_fetch_prices`(`:146,156`)는
키워드입니다.

> **v2.0 규칙: `status_code=` 키워드로 통일합니다.** 위치인자는 두 번째 인자가
> `detail` 인지 `headers` 인지 읽는 사람이 시그니처를 봐야 알 수 있습니다.

## 3. 현재 실태의 문제

### 3.1 422 가 화면에 `[object Object]` 로 뜬다

프런트 공용 래퍼입니다.

```javascript
// app/frontend/js/api.js:30~33
if (!res.ok) {
  const err = await res.json().catch(() => ({ detail: res.statusText }));
  throw new Error(err.detail || res.statusText);
}
```

`detail` 이 **배열**이면 `new Error(배열)` 이 `String(배열)` 로 강제 변환하고, 원소가
객체라 각각 `"[object Object]"` 가 됩니다. 빈 배열 `[]` 은 JS 에서 truthy 라
`|| res.statusText` 폴백도 타지 않아 **빈 메시지**가 됩니다.

`api.js` 가 노출하는 **40개 엔드포인트 전부**가 이 래퍼를 씁니다.

> **올바른 구현이 이미 프런트 안에 있습니다.** `pages/backtest-lab.js:236~242` 가
> `// FastAPI 검증 오류는 detail 이 배열로 옵니다.` 주석과 함께 `d.msg` 를 `' / '` 로
> join 합니다. **공용 래퍼에 반영되지 않았을 뿐입니다.**

### 3.2 같은 의미에 다른 코드를 쓴다

**입력 검증 실패 — 400 과 422 혼용**

| 코드 | 사례 |
| --- | --- |
| 422 | 티커 정규식 위반(`main.py:1176`) · 두 종목 동일(`main.py:1182`) |
| 400 | `market` 열거값 위반(`main.py:1311`) · 필수값 누락(`main.py:328,398`) · 개수 범위(`main.py:866,868`) · 날짜 정합성(`backtest_lab.py:118~128`) · 파일 검증(`tax.py:165,175`) |

필수값 누락·범위 위반·열거값 위반은 **Pydantic 이 잡았다면 전부 422** 였을 항목입니다.
핸들러 안에서 수동 검사하니 400 이 됩니다. 특히 `main.py:1176`(티커 정규식 → 422)과
`main.py:1311`(market 열거값 → 400)은 **성격이 같은데 코드가 다릅니다.**

**외부 데이터 실패 — 5갈래**

yfinance 조회 실패 하나만 놓고도:

| 코드 | 위치 |
| --- | --- |
| 422 | `main.py:1200` · `main.py:1206` |
| 404 | `main.py:2010` · `main.py:2254` · `backtest_lab.py:156` |
| 502 | `main.py:1318` · `backtest_lab.py:146` |
| 503 | `main.py:782` |

### 3.3 실패를 200 으로 숨기는 곳이 8곳

**(가) `error` 필드를 본문에 담고 200 — 4곳**

| 위치 | 형태 |
| --- | --- |
| `main.py:891~895` (`/api/industry/peer`) | `rows[]` 원소에 `{"error": "데이터 수신 실패: ..."}`. **12개 전부 실패해도 200** (`main.py:930`) |
| `main.py:1293~1294` (`/api/market/snapshot`) | `{"status": "error", "error": str(exc2)}` |
| `main.py:1352` (`/api/market/volume-cloud`) | `{"status": "error", "error": str(exc)}` |
| `rag.py:202` (`/api/rag/status`) | `{"error": "컬렉션이 없거나 조회 실패"}` — **상태 조회라 200 이 타당** |

`error` 필드 형태가 셋으로 갈립니다 — `error` 만 / `status`+`error` / `import_error`
(`backtest_lab.py:238`). **프런트는 이 중 어느 것도 공용으로 처리하지 않습니다**
(`api.js:30` 은 `res.ok` 만 봅니다).

**(나) 실패를 감춘 채 200 + 시뮬레이션 데이터 — 4곳**

| 위치 | 동작 |
| --- | --- |
| `main.py:2178` (`/api/home/market-candle`) | `except Exception` 이 함수 전체를 감싸고 **LCG 난수로 OHLCV 를 만들어** `is_simulated: True` 로 200 |
| `main.py:1401~1421,1542~1544` (`/api/macro/realtime`) | GBM 시뮬레이션 + `warning` 문구 |
| `main.py:1637~1669,1796~1798` (`/api/macro/kospi-ex`) | 동일 |
| `main.py:2207~2228,2267` (`/api/home/box-range`) | `is_simulated` 기본값이 **True** 이고 성공해야 False 로 바뀜 |

플래그가 있어 클라이언트가 구분할 수는 있으나, `main.py:2152` 와 `2178` 의 두 return
경로는 **필드 구성이 같아** `is_simulated` 값만으로 판단해야 합니다.

> `main.py:1386` 의 `fetch_error: str | None = None` 은 `main.py:1398` 에서 대입되지만
> **그 뒤 어디에서도 읽히지 않는 죽은 변수**입니다. 실패 원인을 담으려던 흔적만 남고
> 응답에는 실리지 않습니다.

### 3.4 `quant.py` 6개는 에러 처리가 아예 없다

`quant.py:9` 는 `from fastapi import APIRouter` 만 import 합니다. 파일 전체에서 `except`
는 `quant.py:15` 의 모듈 import 폴백 하나뿐입니다.

영향: `/api/quant/portfolio-scenario`(**A등급 F05**) · `backtest` · `portfolio` ·

Pydantic 을 통과한 뒤 matplotlib·numpy 경로에서 예외가 나면 **JSON 이 아닌 500 텍스트**가
나가고, `api.js:31` 의 `res.json()` 이 실패해 사용자는 원인 없이
`"Internal Server Error"` 만 봅니다.

| # | 위치 | 방식 | 문제 |

### 3.6 `renderError` 가 이스케이프하지 않는다

```javascript
// app/frontend/js/api.js:12
export function renderError(msg) { return `<p style="...">오류: ${msg}</p>`; }
```

호출부 10곳이 전부 `innerHTML` 대입입니다 (`crossValidation.js:50` · `kmeans.js:49` ·
`svm.js:48` 등). `msg` 는 서버 `detail` 이고, 아래 5.2절대로 `detail` 에는 외부 시스템
응답 원문이 실립니다.

> 현재 이 10개 뷰는 `ml.py` 계열만 호출하고 그쪽 `detail` 은 `ImportError` 문자열이라
> **실제 도달 가능성은 낮습니다.** 다만 공용 유틸이 이스케이프하지 않는다는 사실은
> 규약에 명시합니다.

### 3.7 OpenAPI 가 선언한 규약과 구현이 다르다

`openapi_docs.py:167` 이 모든 오퍼레이션 설명 끝에
`"**공통 오류:** 요청값 검증 실패 시 422입니다."` 를 붙이고, `:168~170` 이 **503 만**
`setdefault` 로 추가합니다.

| 선언 | 실제 |
| --- | --- |
| "요청값 검증 실패 시 422" | 핸들러 내부 수동 검증은 **400** (3.2절) |
| 등록된 에러 응답 = 503 하나 | 실제로는 400·404·422·502 도 발생 |
| `openapi_docs.py:99` 가 `/run` 의 400 을 **본문에 서술만** | `responses` 에 없음 |

**Swagger UI 만 보고 클라이언트를 짜면 400·404·502 를 대비하지 못합니다.**

## 4. v2.0 HTTP 코드 정책 — 확정

### 4.1 코드별 사용 규칙

| 코드 | 언제 | 누가 잘못했나 |
| --- | --- | --- |
| **200** | 성공. **부분 실패도 200 이면 반드시 플래그를 응답에 넣는다** | — |
| **400** | 요청은 형식상 맞지만 **의미가 성립하지 않을 때**. 예: 토큰도 `anon_id` 도 없음 | 클라이언트 |
| **401** | 인증 토큰이 없거나 유효하지 않음 (F03 신설 API 부터 사용) | 클라이언트 |
| **403** | 인증은 됐으나 남의 리소스 | 클라이언트 |
| **404** | **요청한 리소스 식별자가 없을 때만.** 외부 데이터 부족에는 쓰지 않는다 | 클라이언트 |
| **422** | **입력값 검증 실패 전부.** 타입·범위·열거값·정규식·필수값 | 클라이언트 |
| **500** | 서버 로직 결함. 사용자가 고칠 수 없음 | 서버 |
| **502** | 외부 서비스가 **응답했으나 오류**. DART·Yahoo·Qdrant·LLM 의 4xx/5xx | 외부 |
| **503** | 외부 서비스에 **닿지 못함** 또는 서버 설정 미비. 연결 실패·타임아웃·키 미설정 | 외부·운영 |

### 4.2 외부 데이터 실패는 502/503 으로 모은다

**현행 5갈래(3.2절)를 둘로 줄입니다.**

| 상황 | v2.0 | 현행 예 |
| --- | --- | --- |
| 외부가 오류 응답을 줌 | **502** | `main.py:1318` 은 이미 맞음 |
| 외부에 연결 실패·타임아웃 | **503** | `rag.py:32` 는 이미 맞음 |
| 외부는 정상인데 **데이터가 비어 있음** | **502** | `main.py:1200`(422) → 변경 |
| 요청한 **식별자**가 외부에 없음 | **404** | `main.py:2010` 유지 |

> **F04 의 422 4건 중 2건이 바뀝니다.** "충분한 가격 데이터를 찾지 못했습니다"
> (`main.py:1200`)와 "거래일이 부족합니다"(`main.py:1206`)는 **사용자 입력 문제가
> 아닙니다.** 지금은 Yahoo 가 죽어도 사용자에게 "종목을 잘못 골랐다" 로 보입니다.

### 4.3 입력 검증은 422 로 통일한다

**가능하면 Pydantic 으로 옮깁니다.** 핸들러 안 수동 검사가 400 을 내는 것이 혼용의
원인이므로, 검사를 모델로 올리면 자동으로 422 가 됩니다.

| 현행 | 옮길 곳 |
| --- | --- |
| `main.py:1311` `market` 열거값 | `Field(pattern="^(us\|kr)$")` |
| `main.py:328,398` 필수값 누락 | `Field(min_length=1)` |
| `main.py:866,868` 개수 범위 | `Field(min_length=1, max_length=12)` |
| `main.py:1175` 티커 정규식 | `Field(pattern=...)` — 단 `upper()` 정규화가 먼저 필요해 `field_validator` 로 |

모델로 못 옮기는 **관계 검증**(예: `test_start > train_end`)은 핸들러에 남기되
**422 로 raise** 합니다 — `backtest_lab.py:118~132` 의 400 5건이 대상입니다.

### 4.4 등록할 예외 핸들러 3개

`app/backend/main.py` 에 추가합니다. **본문 형태는 바꾸지 않습니다** — `{"detail": ...}`
그대로 두어야 프런트 40개 호출부를 안 고칩니다.

| # | 대상 | 하는 일 |
| --- | --- | --- |
| 1 | `RequestValidationError` | `detail` 배열을 **한국어 한 문장으로 평탄화**해 `{"detail": "문장"}` 으로 반환. 원본 배열은 `errors` 키에 함께 실어 개발자가 볼 수 있게 함 |
| 2 | `Exception` (미포착 전부) | **500 을 JSON 으로** 반환 (`{"detail": "요청을 처리하지 못했습니다."}`). 예외 원문은 **서버 로그에만**. 현재 500 이 텍스트라 프런트가 파싱 못 하는 문제(3.4절) 해소 |

### 6.2 DART 쿼터 — CN-023 의 정량화

**`POST /api/dart/company-list` 1회 요청(콜드)의 DART 소모량**

| 단계 | 건수 | 근거 |

| `use_emp` 일 때 `_fetch_emp_count` → `empSttus.json` | **len(candidates)** | `main.py:554~559` |

(`main.py:549~552`). 프런트 지역 입력이 자유 텍스트라 비울 수 있습니다

> ⚠ **`limit`(≤200)을 줄여도 외부 호출량은 줄지 않습니다** — 필터를 다 돌린 뒤에

> **정확한 N 은 (확인 필요)** 입니다 — DART 키가 있어야 실측됩니다.

**동시성**: `_load_all_listed_details` 는 `max_workers=30`(`main.py:478`),
`_fetch_emp_count` 배치는 `max_workers=20`(`main.py:555`). **총 호출 수를 줄이지는
않고** in-flight 상한만 정합니다. 둘 다 하드코딩이라 환경변수로 못 낮춥니다.

### 6.6 HTTP 캐시 헤더

**응답에 `Cache-Control` 을 세팅하는 API 엔드포인트는 0개입니다.**

유일한 헤더 조작은 `no_cache_static_assets` 미들웨어입니다 (`main.py:122~138`).

```python
# app/backend/main.py:133~137
if path == "/" or path.endswith((".html", ".js", ".css")):
    response.headers["Cache-Control"] = "no-store, no-cache, must-revalidate, max-age=0"
    response.headers["Pragma"] = "no-cache"
    response.headers["Expires"] = "0"
```

의도는 docstring(`main.py:125~130`)에 있습니다 — 단일 이미지 배포라 옛 셸이 브라우저
캐시에 살아남는 것을 막습니다. 미들웨어 등록 순서상 가장 바깥이라(`:93` GZip →
`:95` CORS → `:122`) 정적 응답에 확실히 붙습니다.

> ⚠ **이미지·JSON·생성 파일은 대상에서 빠집니다** — 확장자 3종만 검사하므로
> `/files/{file_name}`(`ml.py:564~569`)은 `StaticFiles`/`FileResponse` 의 ETag 재검증만
> 적용됩니다.
>
> ⚠ 이 코드는 헤더를 **추가만 하고** `StaticFiles` 가 붙인 `ETag`·`Last-Modified` 를
> 제거하지 않아 두 정책이 공존합니다. `no-store` 가 우선하므로 동작은 맞습니다.

**v2.0**: 조회형 GET 에 `Cache-Control` 을 명시합니다.

## 7. CORS 와 보안 헤더

```python
# app/backend/main.py:95~101
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

> ⚠ **`allow_origins=["*"]` 와 `allow_credentials=True` 를 함께 쓰고 있습니다.**
> 지금은 인증이 없어(`grep` 으로 JWT·세션 코드 0건 확인) 실제 피해가 없습니다.
> 그러나 **[D-05](../00-index/마스터인덱스.md#2-지금-확정된-설계-결정) 로 Supabase 인증을
> 붙이는 순간 문제가 됩니다** — 임의의 사이트가 사용자 자격증명으로 이 API 를 부를 수
> 있게 됩니다.
>
> **(확인 필요)** Starlette `CORSMiddleware` 가 이 조합을 정확히 어떻게 처리하는지는
> 버전에 따라 다릅니다 (`requirements.txt` 에 버전 핀이 없음). 요청 오리진을 그대로
> 반향하는 구현이면 사실상 **모든 오리진 허용 + 자격증명 허용**입니다.

**v2.0**: 인증 도입과 **동시에** 오리진 화이트리스트로 바꿉니다.

| 환경 | `allow_origins` |
| --- | --- |
| 로컬 | `["http://localhost:8000"]` |
| Vercel | 배포 도메인 1개 (첫 배포 후 확정) |

`allow_methods` · `allow_headers` 도 실제 쓰는 것만 남깁니다 — 현재 51개 라우트는
`GET`·`POST` 만 씁니다.

**그 밖의 보안 헤더**(`X-Content-Type-Options` · `X-Frame-Options` ·
`Content-Security-Policy`)는 **하나도 없습니다.** 이 문서 범위 밖이므로
`60-운영/보안과-시크릿.md` 에서 다룹니다. → [CN-034](../00-index/변경이력.md#cn-034)

페이지도 같은 모듈을 씁니다.

### 8.2 에러 표시

| 규칙 | 이유 |
| --- | --- |
| `res.ok` 를 **반드시** 검사한다 | `taxAccounting.js:501` 이 안 함 |
| 본문 파싱은 `.catch()` 로 감싼다 | `ragChat.js:120` 이 안 함 |
| 서버 `detail` 을 **버리지 않는다** | `home.js:131` 이 버림 |
| 에러 문자열은 `textContent` 로 넣는다 | `renderError`(`api.js:12`)가 이스케이프 안 함 |
| 배열 `detail` 처리는 **서버가 담당** | 4.4절 핸들러 1번으로 해소 |

### 8.3 200 인데 실패한 응답

3.3절의 8곳을 프런트가 공통으로 알아볼 수 있게 합니다.

| 플래그 | 의미 | 화면 |
| --- | --- | --- |
