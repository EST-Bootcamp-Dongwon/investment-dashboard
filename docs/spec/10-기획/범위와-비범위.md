## 0. 이 문서가 정하는 선

기획 문서에서 제일 흔한 실패는 **"안 하는 것" 을 안 적는 것**입니다.

이 문서는 세 가지를 확정합니다.

2. v2.0 에서 **하지 않는 것** — 못 해서가 아니라 안 하기로 한 것 (2절)

### 1.2 F27(AI 투자 도우미)에서 확인된 두 가지 — Q-02 답변

이번 세션에서 코드로 확정했습니다. 둘 다 **범위 안**입니다.

**① "확인할 질문 제안" 은 프롬프트에 없습니다.** 오히려 반대로 막혀 있습니다.

`rag.py:129~133` 의 프롬프트 전문:

> "아래 '검색 원문'만 근거로 사용자의 질문에 한국어로 간결하게 답하세요.
> **원문에 없는 사실·숫자·투자 조언을 추가하지 말고**, 정보가 부족하면 부족하다고 밝히세요.
> 출처 번호를 [출처 1]처럼 표시하고 3개 이내의 짧은 문단 또는 목록으로 정리하세요."

원문 이탈을 막는 좋은 프롬프트지만, R-04 가 요구하는 "**확인할 질문을 제안**"
(`docs/07.md:157`) 은 원문에 없는 문장을 만들어야 하므로 지금 규칙에 걸립니다.
"사실·숫자는 원문 밖으로 나가지 말되 **되물을 질문은 제안하라**" 로 분리해야 합니다.
→ [CN-014](../00-index/변경이력.md#cn-014)

**② 임베딩이 의미 검색이 아닙니다.** `rag.py:52` 의 `_hash_embed()` 는
토큰을 SHA-256 으로 해싱해 384차원 버킷에 ±1 을 누적하는 **의존성 없는 해시 임베딩**입니다.

```python
def _hash_embed(text: str, dim: int = 384) -> list[float]:
    """문서 색인 스크립트와 동일한 의존성 없는 384차원 해시 임베딩."""
```

단어가 정확히 겹칠 때만 걸립니다. "분산투자" 로 물으면 "포트폴리오를 나누어 담는다" 는
문서를 못 찾습니다. R-04 가 요구하는 "어려운 용어를 일상어로 바꾸는" 도우미로는 약합니다.
**교체는 범위 안이지만 방법은 세션 4에서 확정**합니다 (pgvector 이관과 함께 결정).
→ [CN-015](../00-index/변경이력.md#cn-015)

> **첫 배포에서 실측**합니다 — 지금은 **(확인 필요)** 입니다.

### 4.1 이 선을 고른 이유

인증(3번)을 넣고 CI/CD(7·8번)를 뺀 것이 이 결정의 핵심입니다.

- **인증은 넣습니다.** Supabase 무료 플랜에 50,000 MAU 가 포함돼 있어
  ([Supabase Billing](https://supabase.com/docs/guides/platform/billing-on-supabase), 2026-08-07 확인)
  **직접 짤 코드가 거의 없습니다.** 반면 "인증 없음" 은 SI 리뷰에서 가장 먼저 지적받는 항목입니다.
  들어가는 비용 대비 올라가는 판정이 가장 큽니다.
- **CI/CD 는 뺍니다.** 파이프라인은 *여러 사람이 자주 배포할 때* 값을 합니다.
  혼자 만들고 심사 전에 몇 번 올리는 프로젝트에서는 관리 비용만 남습니다.

### 4.2 "테스트를 한다" 와 "CI 가 돌린다" 는 다릅니다

R-06 이 요구하는 4단계는 원문(`docs/07.md:175~199`)을 보면
**대부분 사람이 봐야 하는 테스트**입니다.

| 단계 | 성격 | v2.0 처리 |
| --- | --- | --- |
| ① 이해도 | 처음 쓰는 사람에게 보여 주고 되묻는다 | **사람이 수행.** 질문·답변·수정 내역을 기록 |
| ② 시나리오 | 성향·기간·적립금 조합을 바꿔 가며 확인 | **체크리스트로 수행.** 일부는 자동화 가능 |
| ③ 데이터·계산 | 데이터 없는 종목·거래일 부족·같은 종목 2회 | **자동화 가치가 가장 큼** (5.1절) |
| ④ 안전성 | 확정적 표현이 나오지 않는지 | **grep 으로 기계 확인 가능** (개요 4.1절 명령) |

→ **③④는 스크립트로 만들되, `npm test` 처럼 손으로 돌립니다.**
매 푸시마다 자동 실행하는 CI 는 v2.0 비범위입니다.

**Git 연동을 쓰지 않고 CLI 로 올리는 이유가 하나 더 있습니다.**

> "Vercel does not support connecting a project on your Hobby team to Git repositories
> **owned by Git organizations**." — [Limits](https://vercel.com/docs/limits) (2026-08-09 확인)

이 저장소의 `origin` 은 `EST-Bootcamp-Dongwon/investment-portfolio-site` 로
**GitHub 조직 소유**입니다. 즉 Hobby 플랜에서는 GitHub 연동 자동 배포가 애초에 안 됩니다.
"자동화는 안 한다" 는 결정과 플랫폼 제약이 같은 답을 가리킵니다.

> Hobby 플랜의 상업적 이용 가능 여부는 **(확인 필요)** 입니다. 학습용 포트폴리오
> 프로젝트라 현재로선 문제가 없다고 보지만, 문서에서 확인되면 여기에 적습니다.

### 4.4 배포에 앞서 반드시 고쳐야 할 것

Vercel 로 올리기 전에 **지금 코드 그대로는 콜드 스타트에서 죽습니다.**

```python
# app/backend/main.py:54
GENERATED_DIR.mkdir(parents=True, exist_ok=True)
# app/backend/routers/ml.py:16
GENERATED_DIR.mkdir(parents=True, exist_ok=True)
```

둘 다 **모듈 import 시점**에 `app/generated/` 를 만듭니다. 서버리스 환경의 파일시스템은
`/tmp` 를 빼면 읽기 전용이라 여기서 예외가 납니다. **`/tmp` 로 옮겨야 합니다.**
→ [CN-017](../00-index/변경이력.md#cn-017)

반대로 **차트 생성은 안전합니다.** `savefig` 6곳이 전부 `BytesIO` 버퍼로 쓰고
디스크를 건드리지 않습니다 (`main.py:735,845,1082,1522,1786,1946`).

## 5. 애매한 것들 — 여기서 선을 긋습니다

### 5.1 F04 의 예외 처리는 이미 R-06 ③을 상당 부분 만족합니다

R-06 ③(데이터·계산 테스트)이 예시로 든 실수들이 `main.py:1167~1206` 에 이미 있습니다.

| R-06 이 요구한 상황 | 지금 동작 | 위치 |
| --- | --- | --- |
| 종목 코드가 틀린 경우 | 422 · "올바른 종목 코드를 입력해 주세요." | `main.py:1176` |
| 같은 종목을 두 번 고른 경우 | 422 · "서로 다른 두 종목을 선택해 주세요." | `main.py:1182` |
| 가격 데이터가 없는 종목 | 422 · "{종목}의 충분한 가격 데이터를 찾지 못했습니다." | `main.py:1200` |
| 거래일이 적은 종목 | 21일 미만이면 위와 동일 처리, 겹치는 거래일 20일 미만이면 별도 422 | `main.py:1191,1206` |

→ **범위는 "새로 만들기" 가 아니라 "테스트로 고정하고 다른 화면에도 같은 수준을 적용하기"** 입니다.

### 5.2 Qdrant 를 어떻게 할 것인가

Vercel 단일 배포를 택했으므로 **Qdrant 컨테이너를 띄울 곳이 없습니다.**
(`docker-compose.yml:39` 의 `qdrant` 서비스는 로컬 전용이 됩니다.)

| 선택지 | 비고 |
| --- | --- |
| **A. Supabase pgvector 로 이관** | 관리할 무료 서비스가 1개로 줄어듦. `rag.py` 의 Qdrant HTTP 호출을 교체해야 함 |
| **B. Qdrant Cloud 무료 티어 유지** | 0.5 vCPU / 1 GB RAM / 4 GB Disk ([Qdrant Pricing](https://qdrant.tech/pricing/), 2026-08-09 확인). `rag.py` 가 이미 순수 HTTP 호출이라 **URL·API 키만 바꾸면 됨** |

`rag.py` 는 Qdrant SDK 없이 `urllib` 로만 통신하므로(`rag.py:20,25`) B 의 코드 변경이 훨씬 적습니다.
**세션 4(30-데이터)에서 1.2절 ②(임베딩 교체)와 묶어 한 번에 결정합니다.**

### 5.3 "주소가 안 바뀌는가" 를 초반에 확인합니다

임시 터널로 열어 두면 껐다 켤 때마다 주소가 바뀌어 공유한 링크가 다음 날 죽습니다.
Vercel 기본 도메인은 프로젝트에 고정되므로 이 문제가 없습니다.
**자체 도메인 구매는 비범위** — 고정되기만 하면 목적은 달성됩니다.

### 5.4 허브에는 링크 카드로 붙입니다 — iframe 임베드 금지

"만드는 모든 웹은 하나의 허브에 카드로 붙인다" 는 규칙을 이 프로젝트에도 적용합니다.
다만 **임베드가 아니라 링크**여야 합니다.

v2.0 에서 로그인이 생기므로(4절 3번 축), iframe 안에 넣으면 브라우저의
서드파티 컨텍스트 제약 때문에 로그인이 깨집니다. 기술적으로 안 되는 것을 우기면
보안을 포기해야 하고, 그럴 수 없으면 설계를 바꾸는 쪽이 맞습니다.

→ **허브 등록 형태: 새 탭으로 여는 링크 카드.** (개요 C-03)
