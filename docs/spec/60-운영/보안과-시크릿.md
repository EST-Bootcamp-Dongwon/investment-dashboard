## 2. 보안 응답 헤더 — [CN-034](../00-index/변경이력.md#cn-034) 해소

### 2.1 지금은 0종입니다 — 코드와 응답 양쪽에서 확인

```
$ grep -rniE "X-Content-Type-Options|X-Frame-Options|Content-Security-Policy|\
Referrer-Policy|Strict-Transport|Permissions-Policy" app/ --include="*.py" --include="*.html"
(0건)                                                         # 실측 2026-08-10

$ grep -rn "headers\[" app/backend/
main.py:135   response.headers["Cache-Control"] = "no-store, …"
main.py:136   response.headers["Pragma"]        = "no-cache"
main.py:137   response.headers["Expires"]       = "0"
```

**헤더를 만지는 코드는 `no_cache_static_assets`(`main.py:123~138`) 하나뿐이고
전부 캐시 헤더입니다.** 실제 응답으로도 확인했습니다.

```
$ curl -sSD - -o /dev/null http://localhost:18123/api/health   # 실측 2026-08-10
HTTP/1.1 200 OK
date: Mon, 10 Aug 2026 05:14:18 GMT
server: uvicorn
content-length: 15
content-type: application/json
```

**보안 헤더가 한 줄도 없습니다.** `server: uvicorn` 은 오히려 스택을 알려 줍니다.

### 2.2 v2.0 에 넣을 5종

`main.py` 에 미들웨어 하나를 더합니다 ([아키텍처 2.3절](아키텍처.md#23-mainpy-에-남는-것)).

| 헤더 | 값 | 막는 것 |
| --- | --- | --- |
| `X-Content-Type-Options` | `nosniff` | MIME 스니핑. **base64 차트·업로드 응답에 특히 필요** |
| `X-Frame-Options` | `DENY` | 클릭재킹. 이 앱은 iframe 에 실릴 이유가 없음 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 외부로 나가는 경로 노출 |
| `Permissions-Policy` | `geolocation=(), microphone=(), camera=()` | 쓰지 않는 권한을 명시적으로 차단 |
| `Content-Security-Policy` | 2.3절 | XSS |

> `Strict-Transport-Security` 는 **넣지 않습니다.** Vercel 이 HTTPS 를 종단하고
> HSTS 를 자체로 붙입니다. 애플리케이션에서 중복 선언하면 로컬 HTTP 개발이 깨집니다.

### 2.3 CSP 는 단계적으로 갑니다

**지금 코드에 그대로 강한 CSP 를 걸면 화면이 깨집니다.** 이유가 실측돼 있습니다.

| 걸림돌 | 실측 | 출처 |
| --- | ---: | --- |
| 인라인 `style=` | **1,126개** | [CN-056](../00-index/변경이력.md#cn-056) |
| YouTube iframe (F29) | 30개 영상 | [CN-051](../00-index/변경이력.md#cn-051) |
| base64 이미지 (`data:`) | 16곳 | [CN-033](../00-index/변경이력.md#cn-033) |

| 단계 | CSP | 시점 |
| --- | --- | --- |
| 1 | `Content-Security-Policy-Report-Only` 로 관찰만 | v2.0 배포와 동시 |
| 2 | `default-src 'self'; img-src 'self' data:; frame-src https://www.youtube.com; style-src 'self' 'unsafe-inline'` | 위반 목록 확인 후 |
| 3 | `'unsafe-inline'` 제거 | [CN-056](../00-index/변경이력.md#cn-056) 인라인 스타일 정리 후 |

> **3단계를 v2.0 목표로 잡지 않습니다.** 인라인 `style=` 1,126개를 먼저 없애야 하고,
> 그것은 디자인 토큰 작업의 규모입니다. **2단계까지가 v2.0 입니다.**
>
> [배포-전략 3.4절](배포-전략.md#34-결정--matplotlib-을-뺍니다) 결정으로 서버 차트가
> 빠지면 `img-src ... data:` 의 필요가 줄어듭니다. 프런트 렌더로 옮긴 뒤 다시 봅니다.

## 3. CORS — [CN-038](../00-index/변경이력.md#cn-038) 의 (확인 필요) 해소

### 3.1 CN-038 이 남긴 질문

> "**(확인 필요)** Starlette `CORSMiddleware` 가 이 조합
> (`allow_origins=["*"]` + `allow_credentials=True`)을 정확히 어떻게 처리하는지는
> 버전에 따라 다릅니다 (`requirements.txt` 에 버전 핀 없음)."

### 3.2 실제 응답으로 확인했습니다 — 답은 나쁜 쪽입니다

```
$ docker exec <컨테이너> python -c "import starlette; print(starlette.__version__)"
1.4.1                                                          # 실측 2026-08-10

$ curl -sSD - -o /dev/null -H "Origin: https://evil.example.com" .../api/health
access-control-allow-origin: https://evil.example.com          ← * 가 아니라 에코
access-control-allow-credentials: true
vary: Origin

$ curl -X OPTIONS -H "Origin: https://evil.example.com" \
       -H "Access-Control-Request-Method: POST" .../api/market/snapshot
access-control-allow-origin: https://evil.example.com
access-control-allow-credentials: true
access-control-allow-methods: DELETE, GET, HEAD, OPTIONS, PATCH, POST, PUT
access-control-allow-headers: content-type
access-control-max-age: 600
```

**Starlette 1.4.1 은 `*` 를 그대로 보내지 않고 요청한 오리진을 되돌려줍니다.**
브라우저는 `Access-Control-Allow-Origin: *` + `credentials` 조합은 거부하지만,
**구체적 오리진 + `credentials: true` 는 허용합니다.**

> **즉 "임의의 사이트가 자격증명을 실어 이 API 를 부를 수 있는" 상태가 이미 완성돼
> 있습니다.** [CN-038](../00-index/변경이력.md#cn-038) 은 이것을 "인증 도입 시 문제"
> 로 적었는데, 정확히는 **"메커니즘은 지금 살아 있고 훔칠 것이 아직 없을 뿐"** 입니다.
> 인증 코드는 실제로 0건입니다 (`grep -riE "jwt|oauth|session|Depends\(" app/backend/`
> → 실질 0건, `ml.py:510` 은 뉴스 예문 텍스트).

### 3.3 v2.0 설정

```python
# app/backend/main.py:95~101 을 교체
app.add_middleware(
    CORSMiddleware,
    allow_origins=[o for o in os.getenv("CORS_ORIGINS", "").split(",") if o],
    allow_credentials=True,
    allow_methods=["GET", "POST"],        # 현행 7종 → 실제 쓰는 2종
    allow_headers=["Content-Type"],       # 현행 * → 실제 쓰는 1종
)
```

| 환경 | `CORS_ORIGINS` |
| --- | --- |
| 로컬 | `http://localhost:8000` |
| Vercel | `https://<배포 도메인>` |

**`allow_methods` 를 2종으로 줄이는 근거**: 라우트 51개가 전부 `GET`·`POST` 입니다
([API-목록](../40-API/API-목록.md)). `DELETE`·`PATCH`·`PUT` 을 허용할 이유가 없습니다.

> **동일 출처면 CORS 자체가 필요 없습니다.**
> [배포-전략 4.2절](배포-전략.md#42-v20-배치)대로 정적과 함수를 한 도메인에 얹으면
> 브라우저는 CORS 를 태우지 않습니다. **그래도 미들웨어를 남기는 이유**는
> 로컬 개발(별도 포트)과 오설정 시의 안전망 때문입니다.
> **화이트리스트가 비면 아무 오리진도 허용하지 않는 것이 기본값**이 되게 했습니다.

## 4. 시크릿이 URL 쿼리에 실립니다

### 4.1 DART 키 4곳

```
$ grep -n "crtfc_key" app/backend/                             # 실측 2026-08-10
main.py:267   corpCode.xml?crtfc_key=<키>
main.py:457   company.json?crtfc_key=<키>&corp_code=…
main.py:508   empSttus.json?crtfc_key=<키>&…
main.py:2597  fnlttSinglAcnt.json?crtfc_key=<키>&…
```

DART 가 쿼리 파라미터 인증만 제공하므로 **이 방식 자체는 피할 수 없습니다.**
문제는 그 URL 이 예외 문자열을 통해 밖으로 나갈 수 있는가입니다.

### 4.2 실제로 새는지 시험했습니다

`main.py:264~271` 은 예외를 응답에 그대로 붙입니다.

```python
# app/backend/main.py:267~271
url = "https://opendart.fss.or.kr/api/corpCode.xml?" + urllib.parse.urlencode({"crtfc_key": key})
try:
    with urllib.request.urlopen(url, timeout=20) as response: …
except Exception as exc:
    raise HTTPException(status_code=502, detail=f"DART 회사코드 목록 수신 실패: {exc}") from exc
```

같은 구조를 더미 키로 재현했습니다.

| 상황 | 예외 | 키 노출 |
| --- | --- | :---: |
| 호스트 조회 실패 | `URLError: <urlopen error [Errno -2] …>` | **아니오** |
| 스킴 오타 (`htp://`) | `URLError: <urlopen error unknown url type: htp>` | **아니오** |
| 스킴 누락 | `ValueError: unknown url type: 'opendart.fss.or.kr/…crtfc_key=…'` | **예 ⚠** |

**결론: 지금은 새지 않습니다.** URL 이 문자열 리터럴로 하드코딩돼 있어 스킴 누락이
발생할 수 없습니다. 타임아웃·HTTP 오류·DNS 실패 같은 **현실적인 예외는 URL 을 담지
않습니다.**

> **그러나 한 번의 편집으로 새는 구조입니다.** 누군가 base URL 을 환경변수로 빼는
> 순간(값이 비면 스킴이 사라집니다) 키가 502 응답 본문에 실려 브라우저로 나갑니다.
> **과장하지 않되, 구조가 위태롭다는 사실은 기록합니다.**

### 4.3 조치

[CN-036](../00-index/변경이력.md#cn-036) 이 이미 정한 방향과 같습니다 —
**사용자 문장과 서버 로그를 분리**합니다.

키를 다루는 곳이 4군데 → **1개 모듈**이 되어 이 검사를 한 곳에서 할 수 있습니다.

## 5. 개인정보와 입력 검증

### 5.1 `taxpayer_id` — [CN-032](../00-index/변경이력.md#cn-032) 결정

```python
# app/backend/routers/tax.py:15~17
tax_year:      int = Field(default=2024, ge=2020, le=2030)
business_name: str = Field(default="")          # ← 길이 상한 없음
taxpayer_id:   str = Field(default="")          # ← 길이 상한·형식·마스킹 없음

# app/backend/routers/tax.py:339~341  — 계산에 쓰지 않고 응답에 그대로 실음
"tax_year": req.tax_year, "business_name": req.business_name, "taxpayer_id": req.taxpayer_id,
```

**결정: `taxpayer_id` 필드를 삭제합니다.** CN-032 의 선택지 ⓐ 입니다.

| 선택지 | 판단 |
| --- | --- |
| **ⓐ 필드 삭제** | **채택.** 계산에 쓰이지 않으므로 잃는 기능이 0 |
| ⓑ 마스킹해서 에코 | 마스킹 코드를 새로 쓰고 테스트해야 함. 얻는 것 없음 |
| ⓒ 저장하지 않음을 명시 | 문구만으로는 서버 로그·에러 리포트에 남는 것을 못 막음 |

**사업자·주민번호 성격의 값을 받지 않는 것이 가장 싸고 확실합니다.**
F26 은 C등급이고, 세금 계산은 과세표준만 있으면 됩니다.

> `business_name` 은 **남깁니다** — 리포트 제목에 쓰일 수 있는 일반 문자열입니다.
> 다만 **`max_length` 를 붙입니다** (5.2절).

### 5.2 길이 상한이 없는 문자열 필드

| 필드 | 상한 | 비교 |
