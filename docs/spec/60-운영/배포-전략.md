### 3.6 `requirements.txt` 를 다시 써야 합니다

현행 파일에는 **버전 핀이 하나도 없습니다.**

```
# requirements.txt (현행 전문 중 발췌)
fastapi
uvicorn[standard]
numpy
pandas
yfinance
matplotlib
scikit-learn
torch                    ← Vercel 에서 이것이 CUDA 빌드로 설치됩니다
diffusers
opencv-python-headless
```

**`torch` 한 줄이 특히 위험합니다.** `Dockerfile:13~15` 가 CPU 전용 인덱스를 지정해
`torch-2.13.0+cpu` 를 설치하지만(실측: `torch-2.13.0+cpu.dist-info`),
`requirements.txt` 만 읽는 Vercel 빌더는 **PyPI 기본(CUDA 포함) 휠**을 받습니다.
X04 폐기로 `torch` 자체가 빠지므로 결과적으로는 무해하지만,
**"Docker 는 되는데 Vercel 은 안 된다" 가 여기서 발생할 수 있음을 기록합니다.**

핀이 없어 생기는 두 번째 문제 — **재현성**입니다. 지금 이미지에 설치된 버전은
빌드 시점의 최신이고, Vercel 빌드는 **다른 날 다른 버전**을 받습니다.

```
$ docker exec <컨테이너> python -c "import fastapi,starlette,pydantic,uvicorn; …"
fastapi 0.141.1 · starlette 1.4.1 · pydantic 2.13.4 · uvicorn 0.52.1
                                                            # 실측 2026-08-10
```

**v2.0 `requirements.txt` 방침**

1. 배포용과 로컬용을 **분리** — `requirements.txt`(배포) · `requirements-dev.txt`(로컬)
2. 배포용에서 제외: `torch` · `diffusers` · `opencv-python-headless` · `matplotlib`
3. `uvicorn[standard]` → **`uvicorn`** (Vercel 은 자체 ASGI 어댑터를 씁니다)
4. **버전을 핀**한다 — 위 실측 버전을 출발점으로
5. `scikit-learn` 은 **남긴다** (F28 로컬 실행과 `hd_core` 가 씁니다)

> ⚠ **5번에 단서가 있습니다.** F28 은 로컬 전용인데 `sklearn` 은 왜 배포에 남기나 —
> `routers/backtest_lab.py:31` 이 모듈 import 시점에 `hd_core` 를 부르고,
> `hd_core.py:25` 가 `sklearn` 을 import 합니다. **배포본에서 F28 라우터를 빼면**
> `sklearn`·`scipy` 189.7 MB 도 함께 뺄 수 있어 240.1 MB(시나리오 ⑤)가 됩니다.
> 다만 F28 라우터를 빼면 `/api/backtest-lab/*` 3개가 배포본에서 404 가 되므로,
> **화면(`pages/backtest-lab.html`)을 로컬에서만 열도록 안내해야 합니다.**
> v2.0 은 ③(429.8 MB)로 충분하므로 **이 추가 절감은 하지 않습니다.**

## 4. 정적 자산을 함수에서 떼어냅니다

### 4.1 지금은 FastAPI 가 프런트를 통째로 서빙합니다

```python
# app/backend/main.py:2690
app.mount("/", StaticFiles(directory=FRONTEND_DIR, html=True), name="frontend")
```

Docker 단일 컨테이너에서는 옳은 설계입니다. **Vercel 에서는 그렇지 않습니다** —
`styles.css` · `app.js` · 이미지 요청까지 전부 **Python 함수 호출**이 되어
콜드 스타트와 실행 시간을 소모합니다.

### 4.2 v2.0 배치

| 경로 | 처리 | 이유 |
| --- | --- | --- |
| `/api/*` | Python Function | 백엔드 |
| 그 외 전부 | **Vercel 정적 호스팅** | CDN 에서 바로 나감 |

**프런트 코드 변경은 필요 없습니다.**

```javascript
// app/frontend/js/api.js:1
const BASE = '';
```

**동일 출처(same-origin) 가정**이고, Vercel 은 정적과 함수를 **한 도메인**에 얹으므로
`BASE` 를 그대로 두면 됩니다.

### 4.3 `includeFiles` 로 반드시 넣어야 하는 것

`routers/backtest_lab.py:25~28` 이 저장소 루트의 `lean-hyundai/` 를 `sys.path` 에 얹습니다.

```python
_LEAN_HD = _ROOT / "lean-hyundai"
sys.path.insert(0, str(_LEAN_HD))
import hd_core
```

`Dockerfile:22` 가 이 3개 파일을 명시적으로 COPY 합니다.
**Vercel 도 같은 파일을 `includeFiles` 로 넣어야** `/api/backtest-lab/config` 가
`available: true` 를 냅니다. 안 넣으면 `_IMPORT_ERROR` 가 채워지고 503 이 납니다
(`backtest_lab.py:98~108` — 실패 처리는 이미 잘 되어 있습니다).

### 4.4 캐시 버스터 — [CN-062](../00-index/변경이력.md#cn-062) **정정**

CN-062 는 "정적 페이지 두 곳은 옛 CSS 를 계속 씁니다" 라고 적었습니다.
**지금은 그렇지 않습니다.** 실측으로 확인했습니다.

```
$ curl -sSD - -o /dev/null http://localhost:18123/styles.css?v=13   # 실측 2026-08-10
HTTP/1.1 200 OK
etag: "350b29acf5e0202896faea9c83951b0c"
cache-control: no-store, no-cache, must-revalidate, max-age=0
pragma: no-cache
expires: 0
```

`no_cache_static_assets` 미들웨어(`main.py:123~138`)가 `.html`·`.js`·`.css` 에
**`no-store` 를 강제**하므로, `?v=` 값이 무엇이든 브라우저가 캐시하지 않습니다.
**즉 버전 불일치는 지금 무해합니다.**

| 파일 | `styles.css` 버전 |
| --- | --- |
| `index.html:10` | `?v=13` |
| `pages/backtest-lab.html:10` | `?v=10` |
| `pages/youtube.html:10` | `?v=10` |

> **그러나 4.2절대로 정적 자산을 CDN 으로 옮기는 순간 이 미들웨어가 경로에서 빠집니다.**
> 그때 CN-062 가 예언한 버그가 **실제로 발생합니다.** 이전과 동시에 고쳐야 합니다.

**v2.0 캐시 정책**

| 대상 | `Cache-Control` | 무효화 |
| --- | --- | --- |
| `index.html` · `pages/*.html` | `no-cache` (재검증) | ETag |
| `styles.css` · `js/**` · `vendor/**` | `public, max-age=31536000, immutable` | **파일명 해시** |
| `images/**` | `public, max-age=604800` | 파일명 |
| `/api/*` | [공통-응답과-에러 6절](../40-API/공통-응답과-에러.md#6-캐시-정책) | — |

**손으로 올리는 `?v=` 를 없애고 파일명 해시로 갑니다.**
CN-062 가 지적한 "빌드 없이 손으로 버전을 올리는 방식 자체가 원인" 이 맞습니다.

```
$ grep -rn "?v=" app/frontend/index.html app/frontend/pages/*.html   # 실측 2026-08-10
13곳 / 자산 8종
  styles.css          v=13(index) · v=10(backtest-lab) · v=10(youtube)   ← 어긋남
  vendor/mermaid.min.js  v=11.16.0
  js/app.js           v=10
  js/sidebarUI.js     v=2  (3곳 모두 일치)
  js/includeSidebar.js   v=1  (2곳 일치)
  pages/backtest-lab.css v=1 · backtest-lab.js v=1 · youtube.js v=1
```

## 5. 콜드 스타트에서 죽는 코드 — [CN-017](../00-index/변경이력.md#cn-017) 구체화

서버리스 파일시스템은 `/tmp` 를 빼면 읽기 전용입니다.
**`mkdir` 을 하는 곳이 3군데**이고, 위험도가 다릅니다.

```
$ grep -rn "GENERATED_DIR" app/backend/                        # 실측 2026-08-10
main.py:51,54                     GENERATED_DIR = ROOT/app/generated ; .mkdir(…)
routers/ml.py:15,16               같은 경로 ; .mkdir(…)
routers/backtest_lab.py:42,281    ROOT/app/generated/backtest-lab ; .mkdir(…)
```

| 위치 | 시점 | 실패하면 | 조치 |
| --- | --- | --- | --- |
| `main.py:54` | **모듈 import** | **앱 전체가 안 뜸** | **`/tmp` 로** |
| `ml.py:16` | **모듈 import** | **앱 전체가 안 뜸** (main 이 import 함) | **`/tmp` 로** (또는 폐기와 함께 제거) |
| `backtest_lab.py:281` | 요청 처리 중 | 리포트 저장만 건너뜀 | **이미 안전** |

`backtest_lab.py` 는 이미 옳게 되어 있습니다.

```python
# app/backend/routers/backtest_lab.py:279~287
try:
    GENERATED_DIR.mkdir(parents=True, exist_ok=True)
    …
except OSError:
    # 저장에 실패해도 브라우저 다운로드는 되도록 응답은 그대로 돌려줍니다.
    saved = ""
```

**나머지 두 곳을 이 형태로 맞춥니다.** 경로는 환경변수로 뽑아
`GENERATED_DIR = Path(os.getenv("GENERATED_DIR", "/tmp/generated"))` 로 둡니다.

> 차트 생성은 원래 안전합니다 — `savefig` 16곳이 전부 `BytesIO` 버퍼입니다
> ([CN-017](../00-index/변경이력.md#cn-017) 확인). 3.4절 결정으로 이 코드 자체가
> 배포본에서 빠지므로 이 항목은 v2.0 배포에서는 **무쟁점**이 됩니다.

### 6.1 Git 은 두 원격에 모두 올립니다 — [CN-020](../00-index/변경이력.md#cn-020)

```
$ git remote -v                                                # 실측 2026-08-10
gitlab  https://gitlab.com/dev-dongwon05253/est-investment-dashboard.git
origin  https://github.com/EST-Bootcamp-Dongwon/investment-dashboard.git
```

| 원격 | 역할 |
| --- | --- |
| `origin` (GitHub) | **정본**. 상위 저장소의 서브모듈 포인터가 이쪽을 가리킵니다 |
| `gitlab` | **미러**. 한쪽만 올리면 두 원격이 갈라집니다 |

배포는 **Git 연동이 아니라 CLI** 이므로, 푸시와 배포는 별개 동작입니다.
**푸시했다고 배포되지 않습니다.**

> [CN-020](../00-index/변경이력.md#cn-020) 이 남긴 "**(확인 필요)** — Vercel 의 GitLab
> 개인 네임스페이스 연동이 Hobby 에서 허용되는지" 는 **여전히 미확인**입니다.
> [CN-003](../00-index/변경이력.md#cn-003) 이 자동화를 비범위로 정했으므로
> v2.0 에서는 확인하지 않고 넘어갑니다.
