## 2. R-06 원문 (`docs/07.md:175~199`)

> ### AI 웹앱을 테스트하는 방법
> 좋은 포트폴리오 웹앱은 **계산이 돌아가는 것만으로 충분하지 않습니다.**
> 사용자가 결과를 오해하지 않고 실제로 이해했는지 함께 확인해야 합니다.
>
> 1. **이해도 테스트** — 처음 사용하는 사람에게 신호등·자산별 역할·시뮬레이션 차트를
>    보여 주고 짧게 질문합니다. 사용자가 결과를 **매매 지시나 미래 예측으로 오해하면
>    문구와 화면을 고칩니다.**
> 2. **시나리오 테스트** — 안정형·균형형·성장형, 짧은 기간·긴 기간, 월 적립금 유무를
>    비교합니다. **입력값이 바뀌면 설명과 차트가 함께 바뀌는지** 확인합니다.
>    같은 종목 중복 선택·잘못된 종목 코드에도 **이해하기 쉬운 안내**가 나오는지 봅니다.
> 3. **데이터와 계산 테스트** — 가격 데이터가 없는 종목, 거래일이 적은 종목,
>    서로 다른 시장의 종목으로 **오류 처리**를 확인합니다. 신호등 기준과 시뮬레이션
>    가정을 화면이나 도움말에서 볼 수 있게 합니다.
> 4. **안전성 테스트** — '무조건 수익'·'반드시 매수' 같은 **확정적 표현이 없는지**
>    확인합니다. **AI 답변에는 교육용 정보이며 개인별 투자 조언이 아니라는 문구를
>    유지합니다.**

**이 4단계는 대부분 사람이 판단하는 테스트입니다.** 자동화할 수 있는 부분은
2·3단계 일부뿐입니다. 그래서 이 문서는 **수동 체크리스트를 본체로 두고,
자동화는 5절에서 보조로** 다룹니다.

## 3. 4단계를 이 프로젝트에 대입합니다

**중요한 사실 하나** — 4단계가 잡아내야 할 결함이 **이미 대부분 발견돼 있습니다.**
세션 5~7의 변경노트가 그것입니다. 그래서 이 계획은 "무엇을 볼지 막연히 정하는" 것이
아니라 **"이미 아는 결함이 고쳐졌는지 확인하는" 체크리스트**가 됩니다.

**4-1 과 4-2 는 `grep` 으로 판정됩니다.** 이 둘은 5절의 자동화 최소셋에 넣습니다.

### 5.2 넣지 않는 것

| 대상 | 왜 |
| --- | --- |
| **직렬화한 JSON 문자열 비교** | **PostgREST 가 키 순서를 보장하지 않습니다** — `create` 는 `sort_order` 가 먼저이고 `detail` 은 `asset_name` 이 먼저입니다(2026-08-11 실측 → [CN-098](../00-index/변경이력.md#cn-098)). 값은 같으므로 **`==`(순서 무관)로 비교**하고, 표시할 때만 `sort_keys=True` 로 정규화합니다 |
| 외부 API 를 실제로 부르는 테스트 | 쿼터를 먹고, 네트워크에 따라 결과가 흔들립니다. **Supabase 는 예외입니다** — 아래 참고 |

| 브라우저 E2E | 1·2단계는 사람이 봐야 의미가 있습니다 |
| A01~A08 아카이브 | 아카이브 등급. 회귀를 막을 가치가 낮습니다 |

> **Supabase 를 실제로 부르는 것은 왜 예외인가.** DART·Yahoo 는 **남의 쿼터**를 쓰고
> 응답 내용이 시장 상황에 따라 바뀝니다. Supabase 는 **우리 인프라**이고, 우리가 넣은
> 것을 우리가 되읽는 것이라 결과가 흔들리지 않습니다. 무엇보다 **저장·재현이 F03
> 백엔드화의 목적 자체**라 대역으로 대신하면 검증할 것이 남지 않습니다 — 세션 11의
> 로컬 PostgREST 대역은 Auth 응답 코드가 원격과 달랐습니다
> ([CN-097](../00-index/변경이력.md#cn-097)).
>
> 대신 두 가지를 지킵니다. **①** 만든 행은 끝에서 지웁니다(잔여물 0행 확인).
> **②** 503 경로는 원격을 죽이는 대신 `SUPABASE_URL` 만 `http://127.0.0.1:1` 로 바꿔
> 연결 거부를 즉시 받습니다.
