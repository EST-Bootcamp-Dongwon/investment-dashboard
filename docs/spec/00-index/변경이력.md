#### CN-001 · DB 엔진 — **Supabase(Postgres) 로 확정**

- **상태**: **대기** (2026-08-09 결정) · 차단 해제: 세션 4 진행 가능
- **반영처**: `30-데이터/ERD.md` · `30-데이터/테이블-정의서.md` · `60-운영/배포-전략.md`
- **결정 반영됨**: [`10-기획/프로젝트-개요.md`](../10-기획/프로젝트-개요.md) C-01

**결정.** MongoDB Atlas M0 와 비교 검토한 결과 **Supabase(Postgres)** 로 확정합니다.

**비교 — 공식 문서 확인 (2026-08-09 조회)**

| 항목 | MongoDB Atlas M0 | Supabase Free | 유리 |
| --- | --- | --- | :---: |
| 저장 용량 | 0.5 GB | 500 MB | 동률 |
| 무료 단위 | 프로젝트당 클러스터 1개 | 조직당 활성 프로젝트 2개 | 동률 |
| **자동 정지** | **30일** 무활동 | 7일 무활동 (복구 1년 내) | **Atlas** |
| 처리량 | 100 ops/sec · 7일 rolling 10GB in/out | Egress 5 GB | 동률 |
| 백업 | 자동 백업 불가 (`mongodump` 수동) | 무료 다운로드 불가 | 동률 |
| **인증** | **없음 → 직접 구현** | **내장 50,000 MAU** | **Supabase** |
| **벡터 검색** | 공식 문서 **상충** (아래) | pgvector GA | **Supabase** |
| ERD 표현력 | 문서형 | 관계형 | **Supabase** |

출처: [Atlas Free Cluster Limits](https://www.mongodb.com/docs/atlas/reference/free-shared-limitations/) ·
[Supabase Billing](https://supabase.com/docs/guides/platform/billing-on-supabase) ·
[Free Project Pausing](https://supabase.com/docs/guides/platform/free-project-pausing) (전부 2026-08-09 확인)

> ⚠ **MongoDB 공식 문서 2곳이 서로 다릅니다.**
> [Free Cluster Limits](https://www.mongodb.com/docs/atlas/reference/free-shared-limitations/) 는
> Vector Search 를 "Not available" 로 적었고,
> [Vector Search Deployment Options](https://www.mongodb.com/docs/atlas/atlas-vector-search/deployment-options/) 는
> "Free clusters … 쿼리 테스트용으로 사용 가능" 이라고 적습니다.
> 이 불확실성 자체가 A등급 기능(F27)의 기반으로 삼기에 부적절하다고 판단했습니다.

**결정 이유 — 용량이 아니라 기능이 갈랐습니다.**

1. 용량은 0.5GB 로 **사실상 동률**이라 결정타가 되지 못함
2. **인증 50,000 MAU 가 무료로 딸려 옴** → R-08 의 "인증·권한 ❌" 를 코드 거의 없이 해소.
   Atlas 를 택하면 인증을 통째로 직접 짜야 함
3. **pgvector 로 Qdrant 대체 가능** → 관리할 외부 서비스가 줄어듦 (단, 최종 판단은 CN-019 5.2절)
4. 관계형이라 `30-데이터/ERD.md` 가 명확히 나옴 → SI 수준 심사(R-08)에 직접 유리
5. 서울 리전(ap-northeast-2) 활성 슬롯 1개 확보 확인 (2026-08-07 MCP 실측)

**받아들인 대가**: 7일 무활동 정지. 하루 1회 keep-alive 쿼리 또는 데모 전 Resume 로 대응.

**따라오는 제약 (설계에 반드시 반영)**

| 제약 | 대응 |
| --- | --- |
| DB 500MB | 시세 원본을 **넣지 않는다.** pykrx·yfinance 실시간 조회를 유지하고, DB 에는 사용자·포트폴리오·백테스트 **결과 메타와 요약만** 저장 |
| 7일 무활동 시 정지 | 데모·심사 전 Resume 확인. 또는 하루 1회 가벼운 쿼리로 keep-alive |
| 무료는 백업 다운로드 불가 | 스키마를 **마이그레이션 SQL 로 git 에 보관** (로컬이 정본) |
| 활성 슬롯 1개뿐 | 팀 프로젝트에서 또 필요하면 별도 조직을 만든다 |

**결정.** Qdrant 를 **Supabase pgvector 로 이관**하고, 임베딩을

**용량이 걸림돌이 아님을 먼저 확인했습니다** (2026-08-09 실측).

| 항목 | 값 |
| --- | --- |
| `docs/*.md` 8개 → 청크 (`CHUNK_SIZE=1200`, `OVERLAP=200`) | **178** |
| 원문 텍스트 | 353 KB |
| 벡터 768차원 float32 | 534 KB |
| **합계 / 500MB 대비** | **약 0.9 MB / 0.2 %** |

**임베딩 후보 비교 — 전부 공식 문서 2026-08-09 확인**

| 후보 | 무료 | 차원 | 한국어 | 판정 |
| --- | :---: | --- | --- | --- |
| 현행 `_hash_embed` (`rag.py:52`) | ✅ | 384 | 어휘 일치만 | 의미 검색 아님 |
| Supabase Edge 내장 `gte-small` | ✅ | 384 | **영어 전용** | **탈락** |
| `gemini-embedding-001` | ✅ **"Free of charge"** | 3072→768 절단 | (확인 필요) | **채택** |
| 로컬 `sentence-transformers` | ✅ | — | 좋음 | **탈락** (`torch` → 500MB 충돌) |

`gte-small` 탈락 근거 — 모델 카드 원문:
"This model **exclusively caters to English texts**"
([HF 모델 카드](https://huggingface.co/Supabase/gte-small)). 색인 대상 8개가 전부 한국어입니다.

**768 차원을 고른 이유는 pgvector 인덱스 한계입니다.**
`vector` 타입은 최대 16,000 차원이지만 **인덱스는 2,000 차원까지**
([pgvector README](https://github.com/pgvector/pgvector)).
Gemini 기본값 3072 는 **HNSW 인덱스를 만들 수 없습니다.**

**구현 시 반드시 지킬 것 3가지**

1. **수동 L2 정규화** — 공식 문서: "you must manually normalize non-3072 dimensions"
2. **입력 2,048 토큰 상한** — 청크가 1,200자입니다. 토큰 수는 **(확인 필요)**
3. **429 폴백** — 무료 티어 RPM/RPD 가 **(확인 필요)** 이므로 실패 시 해시 임베딩으로 되돌아갑니다.
   차원이 768 ≠ 384 라 **벡터 컬럼을 두 개로 분리**했습니다

**받아들인 대가**: `rag.py:20~68,81~102` 의 Qdrant HTTP 계층을 SQL 로 교체해야 합니다.
Qdrant Cloud 유지보다 변경량이 큽니다. 그럼에도 **운영할 무료 서비스를 1개로 줄이는 값**을
더 크게 봤습니다.

#### CN-002 · LEAN 컨테이너 용량 — **전제가 틀렸습니다**

- **상태**: 대기
- **반영처**: `60-운영/LEAN-백테스트-운영.md`

**제기된 우려.** "42.5GB 짜리 lean 모듈을 전략마다 일일이 받으면 디스크가 부족해진다."

**실측 결과 (2026-08-07).** 그렇지 않습니다.

```
$ docker system df
TYPE      TOTAL  ACTIVE  SIZE      RECLAIMABLE
Images    14     4       62.23GB   43.88GB (70%)

$ docker images | grep -i lean
hyundai-lean-module:local   42.5GB
samsung-lean-module:local   42.5GB
quantconnect/lean:latest    42.5GB
```

`docker images` 의 SIZE 는 **가상 크기**(모든 레이어 합)라서 공유 베이스를 중복 계산합니다.
실제 디스크는 `docker system df` 의 **62.23GB** 이지, 42.5×3 = 127.5GB 가 아닙니다.

이유는 두 파생 이미지가 모두 `FROM quantconnect/lean:latest` 이고
(`lean-hyundai/Dockerfile:1`, `lean-samsung/Dockerfile:1`),
그 위에 **`.py`·`.json`·`.sh` 7개를 COPY 할 뿐**이기 때문입니다.
전략 하나가 늘어도 실제 증가분은 수백 KB 입니다.

**따라서 42.5GB 는 전략 수와 무관하게 딱 한 번 지불합니다.**

**그래도 개선할 것 3가지**

| # | 조치 | 효과 |
| --- | --- | --- |
| 1 | COPY 대신 **볼륨 마운트**로 `/module` 주입 → 파생 이미지를 아예 만들지 않는다 | `--build` 불필요. 전략 추가 = 폴더 추가. `quantconnect/lean` 1벌만 유지 |
| 2 | `docker builder prune` — 빌드 캐시 **2.818GB** | 즉시 회수 |
| 3 | 백테스트 후 미사용 이미지 정리 루틴 (`docker image prune`) | 현재 회수 가능 **43.88GB** |

> 조치 1은 `docker-compose.hd.yaml` 주석이 경고하는
> "`--build` 를 안 붙이면 예전 코드가 그대로 돈다" 문제도 함께 없앱니다.
> **웹앱 요청 안에서 LEAN 컨테이너를 띄우지 않는 현재 설계는 유지합니다**
> (`backtest_lab.py` 는 벡터화 근사로 계산하고, 정본이 필요할 때만 엔진을 돌림).

**LEAN CLI 는 대안이 아닙니다.** `lean init` 이 QuantConnect 계정 로그인을 요구합니다
(엔진 자체는 인증하지 않는데 CLI 의 init 단계가 강제). 무인 실행에 부적합합니다.
