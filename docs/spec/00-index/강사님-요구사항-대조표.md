### 1.1 R-08 세부 — SI 수준 판정

SI 수준을 "실무 인수인계가 가능한 상태" 로 해석해 8개 축으로 나눴습니다.

| 축 | 판정 | 근거 |
| --- | :---: | --- |
| 계층 분리 (Controller→Service→Repository) | ❌ | `main.py` 단일 파일 **115,272 B** 에 라우트 22개. `app/backend/services/` 는 `__init__.py` 만 있는 **빈 껍데기** |
| 영속 저장 (DB) | ❌ | DB 가 **없다**. 모든 결과가 요청-응답 1회로 사라짐. 원본에 있던 MongoDB 는 제거됨 (`docker-compose.yml:6` 주석) |
| 인증·권한 | ❌ | 로그인·세션·JWT 코드가 **하나도 없다** (`grep` 실측) |
| DTO·입력 검증 | 🔶 | `pydantic` `BaseModel` 을 쓰는 라우터가 있으나 (`backtest_lab.py`) 전면 적용은 아님 |
| API 문서화 | 🔶 | `openapi_docs.py` 화이트리스트 방식. **3개 누락** (`/api/market/portfolio-combination` · `/api/quant/portfolio-scenario` · `/api/backtest-lab/*`) |
| 예외 처리·에러 응답 | 🔶 | `HTTPException` 사용처가 있으나 공통 에러 포맷이 없음 |
| 테스트 | ❌ | 자동화 테스트 없음 (R-06 과 같은 원인) |
| 배포·운영 | 🔶 | Docker Compose 4벌 존재. 클라우드 배포 전략은 미정 |

> **R-08 이 R-01 을 끌어내립니다.** R-01 이 🔶 인 이유(프론트 전용)와
> R-08 의 "영속 저장 없음" 은 같은 문제입니다. DB 를 붙이면 두 개가 함께 올라갑니다.

### 2.1 무엇부터 손대야 하나

의존 관계를 따라가면 순서가 나옵니다.

```
DB 엔진 확정 (D-05)
  └─> 영속 저장 (R-08)
        ├─> R-01 포트폴리오 추천 백엔드화  ← A등급 기능이 프론트 전용인 문제
        └─> 인증·권한 (R-08)
계층 분리 (D-02)
  └─> R-08 의 나머지 축 (DTO·에러·문서화)
테스트 계획 수립
  └─> R-06 (4단계 테스트)  ← 계획만 세워도 ❌ 에서 🔶 로 올라간다
면책 문구 공통 컴포넌트화
  └─> R-07 (5/29 → 29/29)  ← 가장 싸게 올릴 수 있는 항목
```

| 순위 | 할 일 | 올라가는 항목 | 비용 |
| --- | --- | --- | --- |
| 1 | DB 엔진 확정 → 영속 저장 | R-01 · R-08 | 큼 |
| 2 | `main.py` 3단계 분해 | R-08 | 큼 |
| 3 | 면책 문구를 공통 컴포넌트로 전 화면 적용 | R-07 | **작음** |
| 4 | 4단계 테스트 계획 문서화 + 시나리오 테스트 자동화 | R-06 | 중간 |
| 5 | RAG 프롬프트에 "확인할 질문 제안" 명시 | R-04 | **작음** |
| 6 | `openapi_docs.py` 화이트리스트 3건 보강 | R-08 | **작음** |

> 3·5·6 은 각각 한 시간 안쪽입니다. 먼저 처리해도 좋습니다.
