## 3. 데이터 모델 — `CONCEPTS`

### 3.1 스키마

```javascript
// app/frontend/js/data/concepts.js  (신설)
export const CONCEPTS = {
  'monte-carlo': {
    id:        'monte-carlo',
    name:      '몬테카를로 시뮬레이션',        // 한국어 기법명 (필수)
    nameEn:    'Monte Carlo Simulation',        // 원어 (필수)
    reading:   '몬테 카를로 시뮬레이션',        // 한국어식 읽기 (필수)
    icon:      'fa-dice',                       // Font Awesome (필수)
    lead:      '한 가지 예측 대신 수천 번의 …', // 한 줄 요약 (필수)
    summary:   '한 번의 미래를 단정하지 않고 …',// 배너용 3~4줄 (필수, PRACTICE_GUIDES 승격분)

    origin:    '몬테카를로는 카지노로 유명한 …',// 이름의 유래 (선택)
    steps: [                                    // 단계 (선택)
      { title: '가정 정하기',      desc: '기대수익률과 변동성 같은 …' },
      { title: '무작위 경로 만들기', desc: '매달 오르내릴 수익률을 …' },
      { title: '결과 모아 보기',   desc: '수천 개 결과의 가운데·낮은 …' },
    ],
    flow:      'flowchart LR\n  A[가정] --> B[경로 5,000개]\n  …',  // mermaid (선택)
    formula:   { expr: 'P10 · P50 · P90', parts: [ … ] },           // 수식 (선택)
    reading_guide: '같은 투자금과 월 납입액이라도 …',                // 읽는 법 (선택)
    code:      { source: 'app/backend/routers/quant.py', snippet: '…' }, // 코드 (선택)
    limits:    '결과는 수익률과 변동성에 관한 가정에 크게 좌우됩니다. …', // 한계 (필수)
  },
  …

```

| 슬롯 | 필수 | 현행 대응 |
| --- | :---: | --- |
| `name` · `nameEn` · `reading` | ✅ | `.{p}-kicker` (`portfolioSimulation.js:28`) |
| `icon` | ✅ | `.{p}-modal-icon` |
| `lead` | ✅ | 헤더 아래 한 줄 |
| `summary` | ✅ | **`PRACTICE_GUIDES[view].text`** |
| `origin` | — | `.{p}-plain-language` |
| `steps` | — | `.monte-carlo-steps` · `.sharpe-parts` |
| **`flow`** | — | **없음 — 신설 (mermaid)** |
| `formula` | — | `.covariance-formula` · `.correlation-formula` · `.sharpe-formula` |
| `reading_guide` | — | `.{p}-example` |
| `code` | — | `.{p}-code-head` + `.{p}-code` |
| `limits` | ✅ | `.{p}-note` |

**필수 6 · 선택 6.** 선택 슬롯이 없으면 그 블록을 **렌더하지 않습니다.**
[CN-008](../00-index/변경이력.md#cn-008) 이 제안한
`{ 기법명, 원어·유래, 단계, 읽는 법, 코드 스니펫, 한계·주의 }` 를 그대로 담고,
**`flow`(mermaid)와 `formula`(수식)를 더했습니다** — 후자는 이미 3개 모달이 쓰고 있습니다.

### 3.2 렌더 순서

```
┌─ concept-modal ─────────────────────────────────────────────┐

│                                                             │

│ ┌ mermaid flowchart ─────────────────────────────────────┐  │  ← flow (신설)

│    같은 투자금과 월 납입액이라도 …                           │
│                                                             │
```

**순서를 바꾸지 않는 이유**: 현행 몬테카를로 모달의 순서가 그대로입니다

`flow` 와 `formula` 만 **단계와 읽는 법 사이**에 끼워 넣었습니다 — 단계를 글로 읽고
그림으로 확인한 뒤 수식으로 정리하는 순서입니다.

## 4. 동작 사양

현행 4개 모달의 동작을 **공통으로 끌어올리면서 접근성 결함 2개를 고칩니다.**

| 항목 | 현행 | v2.0 |
| --- | --- | --- |
| 열기 | 버튼 클릭 → `hidden = false` + `panel.focus()` | 동일 |
| `aria-expanded` 동기화 | ✅ 4개 모두 (`portfolioGuide.js:117`) | 유지 |
| 배경 클릭으로 닫기 | ✅ 4개 모두 (`portfolioGuide.js:122~124`) | 유지 |
| **Esc 로 닫기** | 🔶 **패널 스코프** (`portfolioGuide.js:125~127`) | **`document` 스코프** |
| **포커스 트랩** | ❌ **0건** | **✅ 첫/마지막 포커스 가능 요소 순환** |
| 닫은 뒤 포커스 복귀 | ✅ `help.focus()` (`portfolioGuide.js:113`) | 유지 |
| 스크롤 잠금 | ❌ 개념 모달은 안 함 (엔터프라이즈 모달만 `body.modal-open`) | **`body.modal-open` 적용** |
| `role` · `aria-modal` · `aria-labelledby` | ✅ 4개 모두 | 유지 |

**Esc 를 `document` 로 옮기는 이유**: 지금은 패널에 포커스가 있을 때만 동작합니다.
Tab 으로 패널 밖 요소(모달이 `hidden` 이 아닐 때도 뒤 화면은 포커스 가능)로 나가면
Esc 가 먹지 않습니다. 포커스 트랩을 넣으면 증상은 가려지지만, **두 가지를 함께 고치는
편이 안전합니다.**

## 6. mermaid 도입

### 6.1 지금 상태 — 없는 파일을 로드 중

```html
<!-- app/frontend/index.html:152 -->
<script src="vendor/mermaid.min.js?v=11.16.0"></script>
```

```
$ ls app/frontend/vendor/                        # 실측 2026-08-10
ls: cannot access 'app/frontend/vendor/': No such file or directory
$ git ls-files app/frontend | grep -ci vendor
0
$ grep -rn "mermaid" app/frontend/js/
(0건)
```

| 확인 | 결과 |
| --- | --- |
| `vendor/` 폴더 | **없음** (git 추적도 0건) |
| JS 에서 `mermaid` 참조 | **0건** |
| CSS 의 `.mermaid-*` 규칙 | **15개** (`styles.css:591~634`) — `-view-badge` · `-modal` · `-modal-chart` · `-modal-loading` · `-modal-error` |

**즉 index.html 은 매 로드마다 404 를 냅니다.** 그리고 CSS 에는
**모달·로딩·에러까지 갖춘 mermaid 뷰어 스타일이 완성돼 있습니다.**
기능을 넣으려다 중단됐거나, 넣었다가 파일만 빠진 것으로 보입니다.

### 6.2 결정 — 되살립니다

| 선택지 | 판단 |
| --- | --- |
| ⓐ `<script>` 와 CSS 15개를 지운다 | 개념 모달에 다이어그램이 필요하므로 **되돌려야 함** |
| **ⓑ `vendor/mermaid.min.js` 를 넣고 CSS 를 재사용한다** | **채택** |

**ⓑ 를 고른 이유 3가지.**

1. **스타일이 이미 있습니다.** `.mermaid-modal-chart`·`-loading`·`-error` 까지
   갖춰져 있어 CSS 작업이 0입니다.
2. **CDN 이 아니라 로컬 파일이어야 합니다.** `index.html:7~9` 는 Pretendard 와
   Font Awesome 을 CDN 으로 받는데, mermaid 는 **처음부터 `vendor/` 로 설계돼 있었습니다.**
   오프라인 시연·심사에서 CDN 의존을 줄이는 편이 안전합니다.
3. **[CN-008](../00-index/변경이력.md#cn-008) 이 "단계 설명에 mermaid 플로우차트" 를 명시**했습니다.

**버전은 `11.16.0` 으로 맞춥니다** — 쿼리스트링(`index.html:152`)에 적힌 값입니다.
해당 버전의 실제 배포 존재 여부는 **(확인 필요)** 입니다.

### 6.3 렌더 규칙

| 규칙 | 내용 |
| --- | --- |
| 초기화 | `mermaid.initialize({ startOnLoad: false, theme: 'base', themeVariables: {…} })` |
| 색 | `themeVariables` 를 **CSS 변수에서 읽어** 주입 → [디자인-토큰 7.3절](디자인-토큰.md#73-mermaid-테마) |
| 렌더 시점 | 모달을 **연 뒤** `mermaid.run({ nodes })`. 닫힌 모달을 미리 그리면 폭이 0 |
| 실패 시 | `.mermaid-modal-error` 로 대체 — 모달의 나머지 내용은 그대로 보인다 |
| 다이어그램 크기 | 노드 **7개 이하**. 넘으면 개념을 쪼갠다 |

`flow` 슬롯이 없는 개념은 다이어그램 블록을 렌더하지 않으므로,
**mermaid 로딩 실패가 모달 전체를 막지 않습니다.**

### 6.4 예 — `monte-carlo`

```
flowchart LR
  A["가정<br/>기대수익·변동성"] --> B["경로 5,000개<br/>무작위 생성"]
  B --> C["각 경로에<br/>같은 투자 계획 적용"]
  C --> D["결과 분포"]
  D --> E["10% · 50% · 90%<br/>지점 추출"]
  E --> F["보수적 · 중간 · 긍정적<br/>범위 표시"]
```

노드 6개. 화면이 실제로 하는 일(`quant.py` 스니펫)과 1:1 로 대응합니다.
