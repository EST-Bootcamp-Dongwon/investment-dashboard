### 2.3 ⚠ 한 번의 클릭이 쿼터 수천 건을 태웁니다

가장 중요한 발견입니다.

```python
# app/backend/main.py:466~498
@lru_cache(maxsize=1)
def _load_all_listed_details() -> list[dict]:
    """First call may take ~30 s; subsequent calls are instant."""
    rows = _load_dart_corp_codes()
    listed = [r for r in rows if r["stock_code"]]      # 상장사 전체
    with ThreadPoolExecutor(max_workers=30) as executor:
        future_to_row = {
            executor.submit(_fetch_company_detail, r["corp_code"]): r
            for r in listed                             # 회사 1곳당 company.json 1회
        }
```

**상장사 수만큼 `company.json` 을 부릅니다.** 동시 30스레드입니다.

**상장사 수를 실측했습니다 — 3,981곳입니다** (2026-08-10, `corpCode.xml` 1회 호출 후
`len([r for r in rows if r["stock_code"]])`). 전체 `corp_code` 는 118,681건이고
그중 `stock_code` 를 가진 행이 3,981건입니다. **1회 실행에 3,981건**이 나갑니다.

| 결과 | 내용 |
| --- | --- |
| **일일 한도 대비** | 20,000 ÷ 3,981 = **하루 5.02회**. 목록 1건까지 세면 3,982건이라 **5회** |
| **동시 30스레드** | 코드 `012`(접근할 수 없는 IP) 유발 가능성 — **(확인 필요)**. [CN-084](../00-index/변경이력.md#cn-084) 가 배치 동시성을 **8** 로 낮췄지만 임계값은 여전히 모릅니다 |
| **`@lru_cache` 는 프로세스 메모리** | 서버가 재시작되면 **처음부터 다시** 부릅니다 |

> **"수천 건" 이라는 어림이 맞았습니다.** 다만 하루 가능 횟수가 **5회**라는 것은
> 어림으로는 안 보이던 숫자입니다. 콜드 스타트 5번이면 그날 DART 가 막히고,
> F23 재무제표 조회 같은 **실사용 호출까지 같이 죽습니다.**

#### 서버리스에서는 캐시가 사실상 없는 것과 같습니다

Vercel Python Function 으로 간다는 결정([CN-019](../00-index/변경이력.md#cn-019))과
정면으로 충돌합니다. `@lru_cache` 는 **인스턴스 메모리**라, 콜드 스타트마다 비어 있고
인스턴스가 여러 개면 각자 따로 채웁니다. 즉 **인스턴스 수 × 3,981건**입니다 —
**인스턴스 5개면 그날 한도가 끝납니다.**

**대응 방향** (구현은 60-운영에서 확정)

| # | 조치 | 효과 |
| --- | --- | --- |
| 1 | `_load_all_listed_details()` 결과를 **DB 테이블로 영속화**하고 일 1회만 갱신 | 쿼터가 인스턴스 수와 무관해짐 |
| 2 | 그 갱신을 **로컬 배치**로 돌리고 결과만 올림 | 서버리스에서 30초 배치를 돌리지 않아도 됨 |
| 3 | 동시성 30 → 낮춤 | `012` 위험 완화 |

> **이건 새 제약을 만듭니다.** 지금까지 "시세 원본은 DB 에 넣지 않는다"(C-04)고 했지만,
> **DART 회사 마스터는 시세가 아니라 갱신이 드문 참조 데이터**입니다.
> 넣는 편이 쿼터를 지킵니다. 상장사 수천 행 × 200B ≈ **1MB 미만**이라 용량도 문제없습니다.
> → [CN-023](../00-index/변경이력.md#cn-023) 으로 올립니다.

**세 조치 모두 채택했습니다** ([CN-084](../00-index/변경이력.md#cn-084), 2026-08-10).
테이블은 `dart_company` 이고 정의는
[`테이블-정의서.md` 4.9절](테이블-정의서.md#49-dart_company--dart-회사-마스터)입니다.

**갱신을 전량이 아니라 `modify_date` 증분으로 합니다.** 상장사 3,981곳의
`modify_date` 분포를 세어 보니 최근 7일 변경이 **27건(0.68 %)**, 30일이 82건입니다
(2026-08-10 실측). **영업일당 약 5건**이므로 일일 배치는
`corpCode.xml` 1건 + `company.json` 약 5건 = **약 6건**입니다.

| 방식 | 일일 호출 | 한도 대비 |
| --- | ---: | ---: |
| 전량 갱신 | 3,982 | 19.9 % |
| **`modify_date` 증분** | **약 6** | **0.03 %** |

초기 적재만 1회 3,982건(한도의 19.9 %)이고, **그 뒤로는 664분의 1**로 떨어집니다.
행당 약 280 B × 3,981행 ≈ **1.1 MB** 로 용량 결론도 그대로입니다.

~~이번 세션에서는 결정하지 않습니다~~ → **ⓑ 로 결정됐습니다** (2026-08-10,

그마저 주가지수입니다.

## 4. yfinance — 시세의 주력

### 4.1 사용 범위

### 4.2 한도와 법적 지위

**공식 쿼터 문서가 없습니다.** yfinance 는 Yahoo 의 공개 엔드포인트를 쓰는
**비공식 래퍼**이기 때문입니다. README 원문:

> "yfinance is **not** affiliated, endorsed, or vetted by Yahoo, Inc. It's an
> open-source tool that uses Yahoo's publicly available APIs, and is intended for
> research and educational purposes."
>
> "Remember - the Yahoo! finance API is intended for personal use only."
>
> — [yfinance README](https://github.com/ranaroussi/yfinance) (2026-08-09 확인)

README 는 **rate limit·429·캐싱 요구사항을 언급하지 않습니다.**

**이것이 설계에 주는 뜻**

| 항목 | 판단 |
| --- | --- |
| 한도 | **명시된 한도가 없다 ≠ 한도가 없다.** 조용히 차단될 수 있고 예고 없이 바뀝니다 |
| "personal use only" | 교육용 프로젝트라는 성격과는 맞지만, **상업 서비스로 확장하면 재검토**해야 합니다 |
| 가용성 | Yahoo 가 응답 형식을 바꾸면 라이브러리가 깨집니다. 실제로 자주 있었던 일입니다 |

**대응**: 실패를 정상 경로로 취급합니다. 화면은 "데이터를 가져오지 못했습니다" 를
보여주고 죽지 않아야 합니다. 재현이 필요한 F28 은 **조회 구간을 기록**해
그때의 데이터 범위를 남깁니다([`테이블-정의서.md` 4.6절](테이블-정의서.md#46-backtest_summary--f28-백테스트-요약)).
