## 1. F24 · 금융상품·자산배분 학습

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **C** · **프론트전용** |
| 화면 코드 | `views/financialKnowledge.js` (18.2 KB) |
| 백엔드 | **호출 없음.** `POST /api/quant/financial-knowledge` 가 존재하나 미호출 |

### 1.1 화면이 하는 일

**두 덩어리입니다.**

**① 투자 스타일 → 자산배분 → 미래 금액 추정**

| 입력 | 값 | 근거 |
| --- | --- | --- |
| 투자 금액 | 최소 10만원 (기본 100만원) | `financialKnowledge.js:1~2,136` |
| 투자 기간 | 1년 이상 | `:137` |
| 투자 스타일 | `STYLE_PRESETS` 중 선택 | `:8,138` |
| 시장 시나리오 | `slow` −3 % · `normal` 0 · `fast` +3 % | `:31,139` |

자산별 기대수익·위험이 상수입니다 (`:29~30`).

| 자산 | 기대수익 | 위험 |
| --- | ---: | ---: |
| 주식/ETF | 9.0 % | 20 % |
| 채권 | 3.5 % | 7 % |
| 원자재 | 5.5 % | 17 % |
| 현금 | 2.0 % | 1 % |

**출처가 코드에 없습니다 — (확인 필요).**

**② ETF 비교** — 두 ETF 의 수익률·괴리율·추적오차·보수를 넣으면 가중 점수로 비교합니다.
가중치는 `수익률 0.40 · 괴리율 0.25 · 추적오차 0.20 · 보수 0.15` (`:6`).
**이 가중치의 근거도 코드에 없습니다 — (확인 필요).**

### 1.2 백엔드는 전혀 다른 것을 합니다

`POST /api/quant/financial-knowledge` (`quant.py:325~539`) 가 돌려주는 것:

| 응답 필드 | 내용 | 근거 |
| --- | --- | --- |
| `coverage` | **수업 Part 052~056 의 문서 커버리지 %** | `quant.py:334~375` |
| `diagnostics` | "기존 웹앱은 부분 반영", "보완 웹앱은 반영" 같은 **개발 진행 메모** | `quant.py:521~525` |
| `curriculum` | 5일 커리큘럼 목록 | `quant.py:532~538` |
| `strategies` | 60/40 · 평균분산 · 블랙-리터만 · Risk-Parity 4모델 비교 | `quant.py:439~452` |
| `image` | 4패널 PNG | `quant.py:528` |

**앞의 셋은 제품 기능이 아니라 개발 자기점검 노트입니다.**
`"37~40.md가 Part 052~056의 5일 과정을 모두 포함합니다"`(`quant.py:522`) 같은 문장이
제품 API 응답에 들어 있습니다. 화면과 겹치는 부분도 없습니다 — 화면은 사용자 금액으로
자산배분을 하고, 백엔드는 커리큘럼 점검표를 냅니다.

### 1.3 왜 아무도 부르지 않았는지가 설명됩니다

[CN-006](../00-index/변경이력.md#cn-006) → [CN-027](../00-index/변경이력.md#cn-027) 에서
**`api.financialKnowledge` 가 유일한 진짜 미사용 바인딩**으로 확인됐습니다
(`api.js:60`). 이유가 이제 분명합니다 — **화면이 필요로 하는 것을 주지 않기 때문입니다.**

### 1.4 결정 — CN-028 ② : 엔드포인트를 삭제합니다

| 근거 | 내용 |
| --- | --- |
| 1 | 응답의 3/5 가 **개발 메모**다. 제품 API 가 담을 내용이 아니다 |
| 2 | 화면이 필요로 하는 계산과 **겹치지 않는다** |
| 3 | 호출처가 0곳이고, 그 상태가 최소 3세션 동안 유지됐다 |
| 4 | 삭제하면 라우트 51 → 49 (`rag/search` 와 함께) |

**함께 지울 것**: `app/frontend/js/api.js:60` 의 `financialKnowledge` 바인딩,
`openapi_docs.py:103` 의 `OPERATION_DOCS` 항목.

> **살릴 값이 있는 부분은 따로 기록합니다.** `strategies` 의 자산배분 4모델 비교
> (60/40 · 평균분산 · 블랙-리터만 · Risk-Parity)는 교육적 가치가 있고
> 수업 `모듈 8` 과 직결됩니다. 다만 **지금 화면에 붙일 자리가 없고** C등급 기능이므로
> **v2.1 후보**로 남깁니다. 붙인다면 F06(포트폴리오 최적화)의 탭이 자연스럽습니다.

### 1.5 백엔드화하는가 — 하지 않습니다

F24 화면 자체는 프론트전용으로 둡니다. [05-산업과-기업 6절](05-산업과-기업.md#6-프론트전용-3개에-대한-판단--cn-011-부분-회신)의

### 2.1 하는 일

**캔버스에 그린 의사결정 트리**를 클릭해 내려가면 마지막에 투자 성향 유형과
자산배분이 나옵니다. 노드는 `buildNodes()` 로 생성하고(`:140`),
경로는 `PERIOD_BRANCHES`(`:11`) → `STRATEGIES`(`:47`) 로 이어집니다.

**F03(포트폴리오 추천)과 구조가 같습니다** — 질문에 답하면 미리 정의된 프로필 중
하나가 나오고 자산배분을 보여줍니다. 다른 점은 F03 이 select 3개, F25 가
클릭 가능한 트리라는 표현 방식뿐입니다.

### 2.2 6가지 유형

| 유형 | 기대수익 | 위험 | 기간 | 근거 |
| --- | --- | --- | --- | --- |
| 안전우선형 | 연 2~3 % | 낮음 | 단기 (1년 미만) | `:48~62` |
| 단기수익형 | — | — | — | `:63~77` |
| (이하 4종) | — | — | — | `:78~136` |

각 유형은 `alloc`(자산·비중·색) · `expected` · `risk` · `horizon` · `products` ·
`tags` · `tip` 을 갖습니다.

**② 거래 분류** — 적요 문자열의 키워드 매칭입니다 (`tax.py:22~43,45~55`).

### 3.3 지금 문제

| # | 문제 | 근거 | 심각도 |
| --- | --- | --- | --- |
| 1 | **`taxpayer_id` 가 계산에 안 쓰이면서 응답에 그대로 실린다** | `tax.py:17,341` | **높음** |

## 4. F27 · AI 투자 도우미 (RAG 챗) — R-04

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **A** · 동작 |
| 화면 · 백엔드 | `views/ragChat.js` (133줄) · `routers/rag.py` (3개 라우트) |
| 요구 | **R-04** — 모르는 용어·결과를 질문하면 일상어로 바꾸고 **확인할 질문을 제안** |
| 시나리오 | [SC-04](../10-기획/사용자와-시나리오.md#sc-04--ai-투자-도우미-r-04--f27) |

### 4.1 하는 일

**학습 문서에서 관련 조각을 찾아 답하고, 근거 원문을 나란히 보여줍니다.**
화면은 좌우 2단입니다 — 왼쪽 채팅, 오른쪽 "RAG 검색 원문" 패널 (`ragChat.js:46~62`).

### 4.2 입력

| 입력 | 값 | 근거 |
| --- | --- | --- |
| 질문 | 최대 **500자** (화면) / 2,000자 (서버) | `ragChat.js:54` · `rag.py:72` |
| `top_k` | **5 고정** (화면이 항상 5를 보냄) | `ragChat.js:117` · `rag.py:73` |
| ~~`provider`~~ | **필드 삭제 (2026-08-16)** — 외부 AI 폐기, 절대 제약 1. 화면의 "답변 다듬기" 셀렉트도 함께 사라졌습니다 | [보안과-시크릿 §1.1](../60-운영/보안과-시크릿.md) |

예시 질문 4개를 버튼으로 제공합니다 (`ragChat.js:1`) —
"PER과 PBR의 차이", "ETF 괴리율", "지정가 vs 시장가", "분산투자의 목적".

### 4.3 처리

```
① Qdrant 연결·컬렉션 확인      _require_qdrant     rag.py:94~102   → 503
② 질문을 벡터로                _embed_query        rag.py:62~68
③ 유사 청크 top_k 검색          _search             rag.py:81~91
④ 답변 생성                                        rag.py:176
     **분기 없음** — 원문 3개를 500자씩 잘라 나열   compose_answer()
     (외부 LLM 갈래는 2026-08-16 폐기 · 절대 제약 1)
⑤ answer + sources 반환                            rag.py:177~184
```

**기본 모드는 생성 모델을 쓰지 않습니다.** `_rag_only_answer()` 는 검색된 원문을
그대로 잘라 붙일 뿐입니다 (`rag.py:105~114`). 환각이 원천적으로 불가능하다는 점에서
안전하지만, **"일상어로 바꿔 준다"(R-04)는 못 합니다.**

### 4.4 R-04 판정 — 세 가지가 비어 있습니다

### 4.5 CN-014 조치 — 프롬프트를 두 갈래로 나눕니다

현재 프롬프트(`rag.py:129~134`)는 원문 이탈을 막는 좋은 규칙이지만,
R-04 가 요구한 "확인할 질문 제안"까지 함께 막습니다.

> "아래 '검색 원문'만 근거로 … **원문에 없는 사실·숫자·투자 조언을 추가하지 말고**,
> 정보가 부족하면 부족하다고 밝히세요."

**해법은 "사실"과 "질문"을 분리하는 것입니다.** 규칙을 약화시키지 않고 항목을 더합니다.

```
아래 '검색 원문'만 근거로 사용자의 질문에 한국어로 간결하게 답하세요.
원문에 없는 사실·숫자·투자 조언을 추가하지 말고, 정보가 부족하면 부족하다고 밝히세요.
출처 번호를 [출처 1]처럼 표시하고 3개 이내의 짧은 문단 또는 목록으로 정리하세요.

답변 끝에 "이어서 확인해 볼 것" 항목을 두고, 사용자가 다음에 스스로 확인하면 좋을
질문을 2~3개 제안하세요. 이 질문들은 사실 주장이 아니라 질문 형태여야 하며,
특정 종목·상품을 지목하거나 매매를 권하는 내용이면 안 됩니다.
```

**핵심은 "질문 형태여야 한다"는 제약입니다.** 질문은 사실 주장이 아니므로
원문 이탈 금지 규칙과 충돌하지 않습니다.

**기본 모드(`provider=rag`)에서도 필요합니다.** 생성 모델을 안 쓰므로 LLM 프롬프트로는
해결되지 않습니다. → **검색된 `source_doc` 을 기반으로 한 규칙 기반 후속 질문**
(예: 같은 문서의 인접 청크 제목을 질문형으로 제시)을 붙입니다.
