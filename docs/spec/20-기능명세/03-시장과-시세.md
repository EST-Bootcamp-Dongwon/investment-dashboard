## 1. F10 · 거래량 클라우드

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **C** · 동작 |
| 화면 · 백엔드 | `views/volumeCloud.js` (153줄) · `GET /api/market/volume-cloud` (`main.py:1302~1360`) |

### 1.1 하는 일

**"요즘 어느 종목에 사람이 몰렸나"** 를 타일 크기로 보여줍니다.
타일 면적은 가격이 아니라 **최근 거래량 ÷ 직전 20거래일 평균 거래량** 입니다.

### 1.2 입력

| 입력 | 값 | 근거 |
| --- | --- | --- |
| `market` | `us` (미국 7종) · `kr` (KOSPI 20종) | `main.py:1128~1157` · `volumeCloud.js:78~79` |

그 밖의 입력은 없습니다. 종목은 서버 상수입니다.
`us` 는 Magnificent Seven, `kr` 은 시가총액 상위 20종목입니다.

### 1.3 처리

| 단계 | 내용 | 근거 |
| --- | --- | --- |
| 1 | `market` 이 `us`/`kr` 이 아니면 400 | `main.py:1310~1311` |
| 2 | 해당 시장 티커 전부를 yfinance 로 **2개월치 일괄 수신** | `main.py:1315~1316` |
| 3 | 종목별 마지막 종가·전일 종가·마지막 거래량 추출 | `main.py:1334~1336` |
| 4 | 직전 20거래일 평균 거래량 계산 (`volume.iloc[-21:-1]`) | `main.py:1337~1338` |
| 5 | `volume_ratio = 마지막거래량 / 20일평균` | `main.py:1346` |

**일괄 수신이 실패하면 502**(`main.py:1317~1318`), **개별 종목이 실패하면 그 종목만
`status: "error"`** 입니다(`main.py:1351~1352`). 부분 실패가 전체를 막지 않습니다.

### 1.4 출력

| 필드 | 내용 |
| --- | --- |
| `price` · `change_pct` | 마지막 종가와 전일 대비 |
| `volume` · `average_volume_20d` · `volume_ratio` | 타일 크기의 근거 |
| `latest_data_at` | 종목별 마지막 거래일 |

색은 **상승 빨강 `#fb4b5c` · 하락 파랑 `#3b82f6`** 입니다 (`volumeCloud.js:17~21`).
F01 과 같은 한국식 관행입니다.

### 1.5 잘 돼 있는 것

화면 하단에 **비교 금지 문구**가 있습니다 — "한국과 미국은 거래량 단위와 가격 통화가
다르므로 서로 비교하지 않습니다. 타일 면적은 각 시장 안에서의 …" (`volumeCloud.js:88`).
단위가 다른 값을 나란히 놓을 때 필요한 설명이고, 이 저장소에서 드문 종류의 정직함입니다.

### 1.6 지금 문제

| # | 문제 | 근거 |
| --- | --- | --- |
| 1 | **60초 자동 갱신** — Yahoo 요청 제한에 기여 | `volumeCloud.js:147` |
| 2 | 20일 평균에 **거래정지·신규상장 보정이 없음** | `main.py:1337` |
| 3 | 종목이 서버 하드코딩이라 시가총액 순위가 바뀌어도 그대로 | `main.py:1135~1156` |

### 1.7 v2.0 조치

- 자동 갱신 주기를 **60초 → 5분**으로 늘린다 (일봉 데이터에 60초 갱신은 의미가 없다)
- 한국 종목은 **KRX 공식 API** 로 이관 ([CN-045](../00-index/변경이력.md#cn-045))
- `Cache-Control` 적용 ([CN-037](../00-index/변경이력.md#cn-037))

## 2. F11 · 세계 증시 현황

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **B** · 동작 |
| 화면 · 백엔드 | `views/worldMarkets.js` (130줄) · `POST /api/market/snapshot` (`main.py:1246~1299`) |

### 2.1 하는 일

세계 12개 시장을 **지도 위 마커**와 시가총액 막대로 보여주고, 그중 8개는
**실시간 지수 시세**를 함께 표시합니다.

### 2.2 데이터 — 두 종류가 섞여 있습니다

| 종류 | 출처 | 갱신 |
| --- | --- | --- |
| 국가·거래소·**시가총액·비중**·지도 좌표 | **프런트 하드코딩** (`worldMarkets.js:3~16`) | 없음 |
| 지수 현재가·전일 대비 | `POST /api/market/snapshot` (`:104`) | 60초 (`:128`) |

12개 시장 전부에 `cap`(조 달러)과 `share`(%) 가 상수로 박혀 있습니다 —
미국 62.2 / 42.7 %, 중국 11.5 / 7.9 %, 한국 1.9 / 1.3 % 등.
**이 수치의 기준일과 출처가 코드에 없습니다 — (확인 필요).**

시세를 받는 것은 12개 중 **8개**입니다 (`worldMarkets.js:18`) —
미국·영국·인도·중국·일본·한국·대만·홍콩. 캐나다·독일·사우디·호주는 마커만 있습니다.

### 2.3 지금 문제

| # | 문제 | 근거 | 영향 |
| --- | --- | --- | --- |
| 1 | **시가총액·비중의 기준일이 없다** | `worldMarkets.js:4~15` | 심사에서 "언제 기준이냐"를 물으면 답이 없음 |
| 2 | 시세 8개 / 마커 12개의 **비대칭이 설명되지 않음** | `:18` | 4개는 왜 값이 없는지 화면이 말하지 않음 |
| 3 | 60초 갱신 × 8티커 | `:128` | 상단바(30초) + 홈과 겹쳐 429 위험 |
| 4 | 약한 주의 문구만 있음 | `grep` 실측 2026-08-10 | R-07 은 강한 면책을 요구 |

### 2.4 v2.0 조치

1. `cap`·`share` 에 **기준일과 출처를 명기**하거나, 값을 제거하고 순위만 남긴다
2. 시세가 없는 4개 시장은 화면에서 "지수 미제공" 으로 명시
3. 갱신 주기를 60초 → 5분
4. 한국(KOSPI)은 **KRX 공식 API** 로 이관 ([CN-045](../00-index/변경이력.md#cn-045))

## 3. F12 · 기술적 분석 실습

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **B** · **프론트전용** (백엔드 호출 **0건**) |
| 화면 코드 | `views/technicalChart.js` (671줄 · 40 KB — view 중 두 번째로 큼) |
| 백엔드 | **없음** |

### 3.1 하는 일

**7단계 탭**을 따라가며 기술적 분석의 개념을 하나씩 실습합니다 (`technicalChart.js:646`).

| 탭 | 내용 | 렌더 함수 |
| --- | --- | --- |
| ① 기업 선정 | 종목·시나리오 고르기 | `renderStockSelect` (`:244`) |
| ② 추세분석 | 추세선·고점·저점 | `renderTrend` (`:306`) |
| ③ 이동평균 | MA 교차 | `renderMA` (`:368`) |
| ④ 캔들패턴 | 패턴 식별 | `renderCandle` (`:414`) |
| ⑤ 보조지표 | RSI·볼린저·MACD | `renderIndicators` (`:467`) |
| ⑥ 엘리어트파동 | 파동 세기 | `renderElliott` (`:538`) |
| ⑦ 종합리포트 | 앞 단계 종합 | `renderSummary` (`:577`) |

### 3.2 데이터 — 시세를 전혀 쓰지 않습니다

가격은 **브라우저가 만듭니다.**

```javascript
// technicalChart.js:190~192 — 선형합동생성기(LCG). 시드 기본 42
function genPrices(n = 80, start = 50000, seed = 42, scenario = 'trend_up') {
  let rng = seed;
  const rand = () => { rng = (rng * 1664525 + 1013904223) % 2 ** 32; return rng / 2 ** 32; };
```

시나리오 4종의 추세(drift)가 코드에 고정돼 있습니다 (`:198~202`).

| 시나리오 | drift | 뜻 |
| --- | --- | --- |
| `trend_up` | `+가격 × 0.004` | 상승 추세 |
| `trend_down` | `−가격 × 0.004` | 하락 추세 |
| `sideways` | 20봉 주기로 `±0.001` | 횡보 |
| `wave` | 사인파 + 전반 상승·후반 하락 | 파동 |

기본 종목은 **"삼성전자 / 005930.KS / 시작가 71,000"** 입니다 (`:642`).
**즉 화면에 '삼성전자'라고 적혀 있지만 그려지는 가격은 삼성전자가 아닙니다.**

지표는 전부 브라우저에서 계산합니다 — `calcMA`(`:215`) · `calcRSI`(`:218`) ·
`calcBB`(`:228`) · `calcMACD`(`:234`).

### 3.3 백엔드로 옮겨야 하는가 — **옮기지 않습니다**

[CN-011](../00-index/변경이력.md#cn-011) 이 프론트전용 6개를 묶어 문제로 올렸지만,
**F12 는 백엔드화의 이득이 없습니다.**

| 판단 근거 | 내용 |
| --- | --- |
| 저장할 결과가 없다 | 입력이 "시나리오 선택"이고 출력이 학습용 그림. 재현 대상이 아님 |
| 서버 검증이 필요 없다 | 계산 대상이 난수이므로 서버가 검증할 진실값이 없음 |
| 지표 계산은 이미 정확 | `calcRSI` 등이 `indicators.py:_calc_rsi` 와 같은 정의 |

**진짜 문제는 백엔드 유무가 아니라 '삼성전자'라는 이름표입니다.**
난수 가격에 실존 종목명을 붙이면 학습자가 실제 차트로 오해합니다.

### 3.4 지금 문제

| # | 문제 | 근거 | 심각도 |
| --- | --- | --- | --- |
| 1 | **난수 가격에 실존 기업명·시작가를 붙임** | `:642` | **높음** |
| 2 | 사이드바 링크 없음 | [CN-018](../00-index/변경이력.md#cn-018) | 중간 |
| 3 | 671줄 단일 파일 | — | 낮음 |

**1번은 [CN-035](../00-index/변경이력.md#cn-035)(난수를 실제 시세로 보여줌)와
같은 계열이지만 원인이 다릅니다.** CN-035 는 *조회 실패 시* 난수로 대체하는 것이고,
여기는 *처음부터* 난수인데 실존 이름을 붙인 것입니다.

> 다만 이 화면에는 **강한 면책 문구가 있습니다** (`grep -rlE "교육용|개인별 투자 ?조언"`
> 실측 2026-08-10 — 이 화면은 그 3개 중 하나). 완화 요인으로 기록합니다.

## 4. 세 기능에 공통으로 걸리는 것

### 4.1 Yahoo Finance 의존과 갱신 주기

| 화면 | 주기 | 티커 수 | 근거 |
| --- | ---: | ---: | --- |
| 상단바 (전역) | 30초 | 3 | `app.js:48,383` |
| F01 홈 | 진입 시 + 수동 | 4 + 12 | `home.js:190,248` |
| F10 거래량 클라우드 | 60초 | 7 또는 20 | `volumeCloud.js:147` |
| F11 세계 증시 | 60초 | 8 | `worldMarkets.js:128` |

**F10·F11 을 동시에 열어 두면 분당 15~28건**이 Yahoo 로 나갑니다.
Yahoo Finance 는 비공식 엔드포인트라 공식 한도가 없고, 대신 **429 가 예고 없이**
옵니다. 그 결과가 [CN-035](../00-index/변경이력.md#cn-035) 의 난수 폴백입니다.

### 4.2 그래서 KRX 로 옮깁니다

**KRX 정보데이터시스템 공식 OpenAPI 키가 이 프로젝트에 있고, 살아 있습니다.**

**적용 범위** — 한국 데이터만 옮기고 해외는 yfinance 를 유지합니다.
