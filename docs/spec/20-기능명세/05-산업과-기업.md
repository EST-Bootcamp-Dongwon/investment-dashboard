### 1.2 각 백엔드가 하는 일

| 엔드포인트 | 입력 | 처리 | 출력 |
| --- | --- | --- | --- |
| `/porter` | 5개 힘의 점수 (0~10) | 점수를 그대로 레이더·막대로 그리고 7 / 4 를 경계로 강함·보통·약함 판정 (`main.py:646~649`) | PNG + `avg_score` + `grade` |
| `/sector` | 섹터 ETF 티커 목록 + 기간 | yfinance 로 받아 정규화 수익률·기간 수익률·리스크리턴 3패널 (`main.py:769~856`) | PNG + `summary` |

**`/porter` 는 계산을 하지 않습니다.** 사용자가 넣은 점수를 그림으로 바꿔 줄 뿐입니다.

**"산업 경쟁력 분석"이라는 이름이 자동 분석을 기대하게 만듭니다.**

## 2. F17 · 기업 파이낸셜 분석 · F18 · 재무제표 분석 · F19 · 밸류에이션 실습

세 기능은 **"기업 재무를 읽는 법"** 이라는 하나의 흐름입니다.
F18 이 개념, F17 이 실제 데이터, F19 가 응용입니다.

### 2.1 F17 — 실제 재무 데이터

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **B** · 동작 |
| 화면 · 백엔드 | `views/companyFinancial.js` (118줄) · `POST /api/finance/company-financials` (`main.py:1964~2113`) |

**입력** — `ticker` (기본 `AAPL`) · `period` (`annual`/`quarterly`) (`main.py:1959~1961`).
필드명이 일치합니다 (`companyFinancial.js:87`).

**처리** — yfinance 의 손익계산서·재무상태표·현금흐름표를 받아 다음을 뽑습니다.

| 출력 묶음 | 내용 | 근거 |
| --- | --- | --- |
| `performance` | 매출 · 순이익 · **순이익률(%)** 시계열 | `main.py:2102~2104` |
| `waterfall` | 매출 → 매출원가 → 매출총이익 → 판관비 → 영업이익 → 세금 → 순이익 | `main.py:2059~2068` |
| `debt` | 총부채 · **FCF** · 현금 | `main.py:2107~2111` |
| `earnings` | 최근 20개 분기 EPS 추정치 vs 실제 vs 서프라이즈 | `main.py:2071~2084` |

**FCF = 영업현금흐름 + Capex** 입니다 (`main.py:2039`). Capex 가 음수로 저장되므로
더하기가 맞습니다 — 주석에도 밝혀 놓았습니다 (`main.py:2036`).

**계정과목 이름이 회사마다 달라서** 여러 후보를 순서대로 찾습니다
(`row()` 헬퍼, `main.py:1980~1984`). 예: 영업이익은 `Operating Income` → `EBIT`.
실무적인 처리이고, 수업 `02-preprocessing` 의 결측 처리와 같은 문제의식입니다.

**지금 문제** — 재무제표가 비면 404 (`main.py:2009~2010`)인데, 국내 종목은
yfinance 커버리지가 고르지 않아 **한국 기업에서 자주 빕니다 (확인 필요)**.
DART 를 이미 쓰고 있으므로 **국내는 F23 경로(DART)로 보내는 것**이 맞습니다.

### 2.2 F18 — 백엔드가 필요 없는 학습 콘텐츠

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **B** · **프론트전용** |
| 화면 코드 | `views/financialStatement.js` (275줄) |

**계산이 없습니다.** `statementCards` 라는 상수 배열 하나가 전부이고
(`financialStatement.js:1~193`), 각 카드는 재무제표 종류별로
`summary` · `checks`(항목별 확인 포인트) · `analysis`(읽는 순서) · 이미지를 담습니다.

```javascript
// financialStatement.js:12~18 — 손익계산서 카드의 checks
['매출액',     '전년 또는 전분기 대비 성장률을 먼저 확인합니다.'],
['매출원가율', '매출이 늘어도 원가율이 같이 뛰면 수익성 개선이 제한됩니다.'],
['판관비',     '고정비 성격이 강해 매출 증가 시 영업 레버리지 효과를 만듭니다.'],
```

**백엔드로 옮기지 않습니다.** [CN-011](../00-index/변경이력.md#cn-011) 이 프론트전용
6개를 묶어 문제로 올렸지만, F18 은 **계산도 저장할 결과도 없는 읽기 자료**입니다.
서버를 붙이면 정적 텍스트를 네트워크로 왕복시키는 것 외에 얻는 것이 없습니다.

**다만 정리는 필요합니다** — 학습 콘텐츠가 뷰 파일 안에 하드코딩돼 있어
수정하려면 코드를 고쳐야 합니다. `50-UI` 세션에서 **콘텐츠를 JSON 으로 분리**하는 것을
검토합니다.

### 2.3 F19 — 사용자 가정으로 굴리는 계산기

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **C** · **프론트전용** |
| 화면 코드 | `views/valuation.js` (767줄 · **52.6 KB — view 중 가장 큼**) |

**탭 5개**: 기업 선정 (`:74`) → FCF (`:188`) → DCF (`:309`) → EVA (`:494`) → 리포트 (`:611`).

**모든 숫자를 사용자가 입력합니다.** 초기값은 예시입니다 —
매출 `10000, 11000, 12100, 13310, 14641` · 영업현금흐름 `1500 … 2180` ·
Capex `400 … 480` (`valuation.js:204,208,212`). 실제 기업 데이터가 아닙니다.

**백엔드로 옮기지 않습니다.** 입력이 전부 사용자 가정이고, 계산은 브라우저에서
즉시 반응하는 편이 학습에 낫습니다. 서버 검증의 대상이 될 진실값이 없습니다.

**단, 한 가지는 고쳐야 합니다.** 리포트 탭의 기본 의견이
`"안정적 FCF 창출과 기술 해자를 바탕으로 현재 주가 대비 약 18% 저평가로 판단"`
으로 **미리 채워져 있습니다** (`valuation.js:638`). 사용자가 아무것도 바꾸지 않고
리포트를 만들면 이 문장이 결론으로 나갑니다. **기본값을 비우고 placeholder 로** 돌립니다.

> F19 에는 약한 주의 문구가 있습니다 (`grep` 실측 2026-08-10). 강한 면책은 없습니다.

**입력** (`main.py:151~156`)

비울 수 있습니다** (`:63,136`).

**이 화면이 쿼터를 가장 많이 씁니다.**

```python
# main.py:549~552 — region 이 비면 candidates 가 상장사 전원이 된다
candidates = ([c for c in all_companies if region in c.get("adres", "")]
              if region else list(all_companies))
```

| 소모처 | 건수 |
| --- | --- |
| `_load_all_listed_details()` (콜드) | 상장사 수 **N** 건 (`main.py:478~482`) |
| `_fetch_emp_count()` (종업원 조건 사용 시) | 후보 수만큼, 최대 **N** 건 (`main.py:555~559`) |
| **합계** | **최대 2N 건** |

DART 일일 한도는 **20,000건**입니다
([개발가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018), 2026-08-09 확인).
**N 실측은 DART 키로 `corpCode.xml` 을 받아야 알 수 있어 (확인 필요)** 이지만,
국내 상장사는 2,000곳 이상이므로 **한 번 조회에 수천 건**입니다.

> ⚠ **`limit` 을 줄여도 소용없습니다.** 필터를 전부 돌린 뒤에 자르기 때문입니다
> (`main.py:574`). 사용자가 `limit=1` 을 넣어도 외부 호출량은 같습니다.

동시성도 높습니다 — `_load_all_listed_details` 가 30 스레드(`main.py:478`),
`company-list` 가 20 스레드(`main.py:555`)입니다. DART 응답 `012`(IP 차단) 위험이 있습니다.

**v2.0 조치** ([CN-037](../00-index/변경이력.md#cn-037) 의 화면 쪽 대응)

1. **`region` 빈 값을 금지**한다 (422). 지금은 "전체 조회"가 되어 최악의 경로가 열려 있다
2. `limit` 을 **필터 이전**에 적용
3. 회사 마스터를 **DB 참조 테이블**로 옮기고 일 1회 배치 갱신 ([CN-023](../00-index/변경이력.md#cn-023))
4. 동시성 상한을 환경변수로
5. **실패는 캐시하지 않는다**

### 3.4 F22 · 그룹사 계열사 네트워크

| 항목 | 값 |

| 등급 · 상태 | **C** · 동작 |
| 화면 · 백엔드 | `views/groupNetwork.js` · `POST /api/dart/group-network` (`main.py:389~449`) |

**하는 일** — 그룹명(예: "삼성")으로 시작하거나 포함하는 상장사를 모아
**pykrx 시가총액**을 붙이고 큰 순서로 정렬합니다.

| 단계 | 내용 | 근거 |

| 1 | 이름이 그룹명으로 **시작**하는 곳 우선, 그다음 포함 | `main.py:404~408` |
| 2 | pykrx 로 오늘 시가총액 조회 | `main.py:411~413` |

| 4 | 시가총액 내림차순 정렬 + KOSPI/KOSDAQ 개수 집계 | `main.py:435~439` |

3번은 좋은 처리입니다. 다만 **월요일 새벽이나 연휴에는 어제도 비어** 시가총액이
전부 0 으로 나옵니다 (`_pykrx_market_data` 가 실패 시 `{}` 를 반환하고 그것이
날짜 키로 캐시됨 — `main.py:381~386`).

**한계** — "계열사"를 **이름 문자열로만** 판단합니다. 지분 관계를 보지 않으므로
`삼성` 검색에 지분 관계가 없는 동명 기업이 섞일 수 있고, 반대로 이름이 다른
계열사는 빠집니다. **화면이 이 한계를 밝히지 않습니다.**

### 3.5 F23 · DART 재무 AI 분석

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **B** · 동작 |
| 화면 · 백엔드 | `views/dartFinancialAnalysis.js` (24.9 KB) · `POST /api/dart/financial-analysis` (`main.py:2580~2679`) |

**하는 일** — DART 재무제표를 받아 **비율 10종 → 100점 점수 → 등급 → 서술형 분석**
까지 만듭니다. 이 저장소에서 가장 완성도 높은 분석 파이프라인입니다.

#### 처리 흐름

```
① 회사 개요 조회                _fetch_company_detail    main.py:2586
② 연결재무제표(CFS) 시도         _fetch_fin("CFS")        main.py:2609
③ 실패하면 별도재무제표(OFS)      _fetch_fin("OFS")        main.py:2612
④ 계정과목 파싱 (14종)           _parse_dart_amounts      main.py:2283~2324
⑤ 재무비율 10종 계산             _calc_dart_ratios        main.py:2327~2359
⑥ 100점 점수 + 항목별 배점        _score_financial_health  main.py:2362~2411
⑦ 등급 A+~F, 판정 4단계          main.py:2627~2631
⑧ 규칙 기반 서술 생성            _generate_dart_analysis  main.py:2414~2577
```

②→③ 폴백이 정확합니다. 연결재무제표가 없는 회사(비지주·단일법인)를 별도로 받습니다.

#### 점수 배점

| 항목 | 배점 | 만점 조건 | 근거 |
| --- | ---: | --- | --- |
| 부채비율 | 20 | 50 % 미만 | `main.py:2383~2384` |
| 영업이익률 | 20 | 20 % 이상 | `main.py:2387~2389` |
| ROE | 15 | 20 % 이상 | `main.py:2392~2394` |
| 유동비율 | 15 | 200 % 이상 | `main.py:2397~2399` |
| 매출 성장률 | 15 | 15 % 이상 | `main.py:2402~2404` |
| 이익잉여금 비율 | 15 | 70 % 이상 | `main.py:2407~2409` |

> 즉 **데이터가 빈 기업이 중간 점수를 받습니다.** 재무제표 파싱이 실패한 회사가
> "보통" 으로 보이게 되므로, **결측은 점수가 아니라 경고로 다뤄야 합니다.**

## 4. F23 의 투자의견 — R-07 과 정면으로 부딪칩니다

### 4.1 무엇이 나오는가

```python
# app/backend/main.py:2542~2565
if score >= 75:   outlook = "매수(Buy)";        outlook_eng = "BUY";   outlook_color = "green"
elif score >= 55: outlook = "중립(Hold)";       outlook_eng = "HOLD";  outlook_color = "yellow"
else:             outlook = "관망(Sell/Wait)";  outlook_eng = "SELL";  outlook_color = "red"
```

화면은 이것을 **큰 배지와 색 블록으로** 강조합니다
(`dartFinancialAnalysis.js:167~171,220~226`). 면책 문구는 그 아래
`※` 로 작게 붙습니다 (`:259`).

### 4.2 왜 문제인가

R-07 원문은 **"확정적 표현 금지, 교육용이며 개인별 투자조언이 아님을 유지"** 입니다
([대조표 R-07](../00-index/강사님-요구사항-대조표.md#1-대조표)).

| 관점 | 판단 |
| --- | --- |
| "매수 / 관망" 은 확정적 표현인가 | **그렇습니다.** 재무비율 요약이 아니라 **행동 지시**입니다 |
| 근거가 충분한가 | 재무비율 6개뿐입니다. 주가·밸류에이션·산업 국면이 하나도 안 들어갑니다 |
| **점수 75점이 "매수"인 근거** | **코드에 없습니다 — (확인 필요)** |
| 면책이 상쇄하는가 | 배지는 크고 면책은 작습니다. 시선의 무게가 다릅니다 |

**결정적으로, 밸류에이션 없이 매수 의견을 내는 것은 방법론적으로도 성립하지 않습니다.**
아무리 재무가 좋아도 주가가 이미 반영했으면 매수가 아닙니다.
같은 프로젝트의 F19(밸류에이션 실습)가 바로 그 이야기를 하고 있습니다.

### 4.3 v2.0 조치 — 의견이 아니라 상태로 바꿉니다

| 지금 | v2.0 |
| --- | --- |
| `매수(Buy)` / `BUY` / 초록 | **`재무 양호`** — 점수와 등급만 |
| `중립(Hold)` / `HOLD` / 노랑 | **`보통`** |
| `관망(Sell/Wait)` / `SELL` / 빨강 | **`재무 취약 — 확인 필요 항목 있음`** |

`outlook_reason` 도 "중장기 투자 매력이 높습니다"(`main.py:2548`) 대신
**"어떤 지표가 점수를 올렸는지"** 를 그대로 말하게 바꿉니다. `breakdown` 에
항목별 점수가 이미 들어 있으므로(`main.py:2377`) 추가 계산이 없습니다.

이 변경은 **`analysis.paragraphs` 의 재무 서술은 건드리지 않습니다.**
부채비율·수익성·성장률 문단(`main.py:2452~2539`)은 사실 서술이라 R-07 위반이 아닙니다.

→ [CN-046](../00-index/변경이력.md#cn-046)

- `taxpayer_id` 와 같은 계열의 문제는 여기 없음 — F23 은 식별자를 에코하지 않는다
