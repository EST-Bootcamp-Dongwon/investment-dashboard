## 1. F13 · 거시경제 현황 (실시간)

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **B** · 동작 |
| 화면 · 백엔드 | `views/macroRealtime.js` (7.5 KB) · `POST /api/macro/realtime` (`main.py:1362~1544`) |

### 1.1 하는 일

금리·유가·주가지수·환율 등을 함께 놓고 **① 가격 추이 ② 정규화 누적수익률
③ 상관관계 히트맵 ④ 기간 수익률 막대** 네 패널을 PNG 한 장으로 그립니다.

### 1.2 입력

| 입력 | 값 | 기본 | 근거 |
| --- | --- | --- | --- |
| `tickers` | 체크박스 다중 선택 | `^TNX`·`CL=F`·`^GSPC`·`^KS11`·`GC=F`·`EURUSD=X` | `main.py:1095` · `macroRealtime.js:25` |
| `period` | `1mo`~`5y` | `1y` | `main.py:1096` |

필드명이 일치합니다 (`macroRealtime.js:116`).

선택 가능한 지표는 10종입니다 (`main.py:1115~1126`) — 위 6종에
`BTC-USD`·`^IRX`(미국 3개월)·`^VIX`·`DX-Y.NYB`(달러인덱스)를 더한 것입니다.

### 1.3 지금 데이터의 성격 — 한국 공식 통계가 없습니다

10종을 성격별로 나누면 이렇습니다.

| 성격 | 지표 | 개수 |
| --- | --- | ---: |
| 미국 금리 | `^TNX`(10년) · `^IRX`(3개월) | 2 |
| 원자재 | `CL=F`(WTI) · `GC=F`(금) | 2 |
| 주가지수 | `^GSPC` · `^KS11` | 2 |
| 환율 | `EURUSD=X` · `DX-Y.NYB` | 2 |
| 기타 | `BTC-USD` · `^VIX` | 2 |

**한국 기준금리·소비자물가·원/달러 환율이 하나도 없습니다.**
`^KS11`(KOSPI) 하나가 유일한 한국 항목이고, 그것도 거시지표가 아니라 주가지수입니다.

화면 이름은 "거시경제현황"이고 개념 설명은 "금리·유가·환율처럼 경제의 온도를 알려주는
숫자를 한곳에" 라고 적혀 있는데(`app.js` `PRACTICE_GUIDES`), **정작 한국 경제의 온도계가
빠져 있습니다.** 이것이 CN-024 를 "채우는" 쪽으로 결정한 첫 번째 이유입니다.

## 2. F14 · 거시경제 시뮬레이션 (GBM)

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **B** · 동작 |
| 화면 · 백엔드 | `views/macroSimulation.js` (5.7 KB) · `POST /api/macro/simulation` (`main.py:1832~1956`) |

### 2.1 하는 일

**실제 데이터를 전혀 쓰지 않습니다.** 거시지표 6종이 기하 브라운 운동(GBM)으로
움직인다고 가정하고, **경기 4국면**을 얹어 가상의 시계열을 만듭니다.

이것은 문제가 아니라 **의도된 설계**입니다. 화면 이름이 "거시경제현황 2 (시뮬레이션)"
이고(`app.js:80`), 개념 설명도 "가능한 미래 길을 여러 번 그려 보는 방법…
하나의 정답을 맞히기보다" 라고 밝힙니다.

### 2.2 입력

| 입력 | 범위 | 기본 | 근거 |
| --- | --- | --- | --- |
| `n_days` | 60 ~ 1,260 으로 **서버가 clamp** | 252 | `main.py:1850` · `macroSimulation.js:35` |
| `seed` | 정수 | 42 | `main.py:1830` · `:40` |

필드명이 일치합니다 (`macroSimulation.js:53~55`).
`seed` 를 사용자가 바꿀 수 있어 **다른 우연을 볼 수 있습니다** — F05~F09 와 다른 점입니다.

### 2.3 처리

| 기준금리 (%) | 3.50 | +0.05 | 0.08 |
| CPI (전년비 %) | 3.20 | +0.02 | 0.12 |
| WTI 유가 ($) | 78.0 | +0.03 | 0.30 |
| USD/KRW | 1,320 | −0.01 | 0.07 |
| KOSPI | 2,650 | +0.06 | 0.18 |
| S&P 500 | 5,200 | +0.08 | 0.16 |

근거: `main.py:1858~1865`. **이 값들의 출처가 코드에 없습니다 — (확인 필요).**

경기 국면은 기간을 4등분해 추세에 배수를 곱합니다 (`main.py:1868~1870`).

## 3. F15 · KOSPI 제외 지수 분석

| 항목 | 값 |
| --- | --- |
| 등급 · 상태 | **B** · 동작 |
| 화면 · 백엔드 | `views/kospiExcluded.js` (12.8 KB) · `POST /api/macro/kospi-ex` + `GET /api/macro/kospi-ex/meta` (`main.py:1589~1823`) |

### 3.1 하는 일

**"삼성전자를 빼면 KOSPI 는 어떻게 움직였을까"** 에 답합니다.
종목이나 섹터를 골라 제외하면, 그 기여분을 걷어낸 조정 지수를 실제 KOSPI 와 비교합니다.

질문 자체가 좋습니다 — KOSPI 는 삼성전자 하나가 21 % 를 차지해서
"지수가 올랐다"가 "시장이 좋다"와 다를 수 있다는 걸 눈으로 보여줍니다.

### 3.2 입력

| 입력 | 값 | 근거 |
| --- | --- | --- |
| `exclude_tickers` | 종목 코드 목록 | `main.py:1584` |
| `exclude_sectors` | 섹터명 목록 | `main.py:1585` |
| `period` | `1mo`~`3y` | `main.py:1586` |

선택지는 `GET /api/macro/kospi-ex/meta` 가 내려줍니다 (`main.py:1814~1823`).

### 3.3 처리 — 계산식

```
제외 종목 기여도  contrib_t = Σ (종목 비중 × 종목 일간수익률)      main.py:1683~1688
조정 수익률       r_adj = (r_KOSPI − contrib) / (1 − 제외비중합)   main.py:1691
누적 지수         (1 + r) 누적곱 × 100                            main.py:1694~1697
```

제외 비중 합이 **95 % 이상이면 400** 입니다 (`main.py:1616~1617`).

### 3.4 가장 큰 한계 — 구성종목이 하드코딩이고 58.6 %만 덮습니다

```python
# app/backend/main.py:1549~1578
KOSPI_COMPONENTS = [
    {"ticker": "005930.KS", "name": "삼성전자", "sector": "반도체", "weight": 0.210},
    …
]
```

| 항목 | 값 | 측정 |
| --- | ---: | --- |
| 등록 종목 수 | **28** | `main.py:1549~1578` |
| **가중치 합계** | **58.6 %** | 28개 `weight` 합산 (실측 2026-08-10) |
| 기준일 | **없음** | 코드에 주석·출처 없음 → **(확인 필요)** |

**두 가지 결과가 따라옵니다.**

1. **나머지 41.4 % 는 존재하지 않는 것처럼 계산됩니다.** 분모 `1 − 제외비중합`
   (`main.py:1691`)이 "제외하고 남은 전체"를 뜻해야 하는데, 실제로는
   28종목 밖의 시장 전체가 KOSPI 수익률 안에 섞인 채로 남습니다.
2. **비중이 갱신되지 않습니다.** 삼성전자 21.0 % 가 언제 기준인지 알 수 없고,
   시가총액이 바뀌어도 그대로입니다.

### 3.5 시뮬레이션 폴백이 여기에도 있습니다

`^KS11` 을 못 받거나 제외 종목 중 하나라도 실패하면 **전부 난수로 대체**됩니다
(`main.py:1639~1669`). LCG 시드 `12345` 고정입니다 (`main.py:1642`).

> ✅ **화면이 표시합니다** — `kospiExcluded.js:196~199` (실측 2026-08-10).
> F13 과 마찬가지로 [CN-035](../00-index/변경이력.md#cn-035) 의 "(확인 필요)" 가 해소됩니다.

다만 조건이 넓습니다. `is_simulated` 는 `tickers_needed` 중 **하나라도** 실패하면
`True` 가 되고(`main.py:1636~1637`), 그러면 `^KS11` 이 정상이었어도 **전부 버리고**
난수로 갑니다(`main.py:1639`). 제외 종목을 많이 고를수록 폴백 확률이 올라갑니다.

| `KOSIS_API_KEY` | **국가통계포털** | ✅ **정상** — 주제별 목록 수신 |
| `FRED_API_KEY` | **미국 세인트루이스 연은** | ✅ **정상** |
| `KRX_API_KEY` | **KRX 정보데이터시스템** | ✅ **정상** → [03-시장과-시세 4.2](03-시장과-시세.md#42-그래서-krx-로-옮깁니다) |
| `FINANCE_SUPERVISORY_API_KEY` | 금융감독원 (서비스 미상) | ⚠ **(확인 필요)** — 5절 |
| `HUGGINGFACE_ACCESS_TOKEN` | HuggingFace | X04 폐기 대상이라 미사용 |

> ⚠ **이름 불일치.** `docker-compose.yml:26` 은 `BOK_API_KEY` 인데 실제 키 이름은
> `ECOS_API_KEY` 입니다. 같은 서비스(한국은행 ECOS)이므로 **`ECOS_API_KEY` 로 통일**합니다.

### 4.2 ECOS — 통계표 코드까지 실검증

추측이 아니라 **API 로 확인한 코드**입니다.

| 지표 | 통계표 | 항목 코드 | 주기 | 제공 구간 |
| --- | --- | --- | --- | --- |
| 한국은행 기준금리 | `722Y001` | `0101000` | D · M · A | 19990506 ~ **20260807** |
| 원/미국달러 (매매기준율) | `731Y001` | `0000001` | D | 19640504 ~ **20260810** |
| 소비자물가지수 (총지수) | `901Y009` | `0` | M · Q · A | 196501 ~ **202607** |

```
$ curl "https://ecos.bok.or.kr/api/StatisticSearch/<키>/json/kr/1/2/722Y001/D/20260801/20260810/0101000"
    20260801 한국은행 기준금리 = 2.75 연%          # 실측 2026-08-10
    20260802 한국은행 기준금리 = 2.75 연%
```

호출 형식: `/api/StatisticSearch/{키}/json/kr/{시작행}/{끝행}/{통계표}/{주기}/{시작}/{종료}/{항목}`

### 4.3 FRED — 미국 기준금리

```
$ curl "https://api.stlouisfed.org/fred/series/observations?series_id=FEDFUNDS&…"
    2026-07-01 = 3.63 %                            # 실측 2026-08-10
```

`FEDFUNDS` 는 월별이고 1954-07 부터 제공됩니다. **한·미 기준금리를 나란히 놓으면
금리차가 나오고, 그것이 환율 설명의 출발점이 됩니다.**

### 4.4 쿼터 — 여전히 미확인

| 출처 | 일일 한도 | 확인 시도 |
| --- | --- | --- |
| DART | **20,000건** | [개발가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018) (2026-08-09) |
| ECOS | **(확인 필요)** | [ECOS API 가이드](https://ecos.bok.or.kr/api/#/DevGuide/DevSpecification) 가 SPA — 본문에 수치 없음 (2026-08-10) |
| KOSIS | **(확인 필요)** | [KOSIS 공유서비스](https://kosis.kr/openapi) 가 SPA. 2026-07-09 자 "분당 호출건수 제한" 공지 존재만 확인 |
| FRED | **(확인 필요)** | 이번 세션에서 확인하지 않음 |
| KRX | **(확인 필요)** | 이번 세션에서 확인하지 않음 |

> **2차 자료의 숫자는 적지 않습니다.** 공식 출처에서 확인되면 그때 채웁니다.
> 대신 **호출량을 설계로 줄입니다** — 거시지표는 일·월 단위라 하루 1회 갱신이면
> 충분하고, DB 참조 테이블에 넣으면 화면 진입마다 외부를 부르지 않아도 됩니다.

### 4.5 설계 원칙 — 거시지표는 DB 에 넣습니다

[C-04](../10-기획/프로젝트-개요.md)("시세 원본을 DB 에 넣지 않는다")의 **예외**로 둡니다.
[CN-023](../00-index/변경이력.md#cn-023) 이 DART 회사 마스터에 적용한 것과 같은 논리입니다.

| 기준 | 시세 (넣지 않음) | 거시지표 (넣음) |
| --- | --- | --- |
| 갱신 빈도 | 초·분 | **일·월** |
| 행 수 | 종목 × 거래일 = 수백만 | **지표 6종 × 수천일 ≈ 2만 행 미만** |
| 용량 | GB 급 | **수 MB** |
| 재조회 비용 | 낮음 | 쿼터 소모 |

**하루 1회 배치로 채우고, 화면은 DB 만 읽습니다.** 배치는 로컬에서 돌립니다
([CN-023](../00-index/변경이력.md#cn-023) ⓑ 와 같은 방식).

> 테이블 정의는 `30-데이터/테이블-정의서.md` 에 **아직 없습니다.** 스키마 추가가
> 필요하므로 세션 9(정합성 검증)에서 함께 반영합니다 → [CN-044](../00-index/변경이력.md#cn-044).
