## 0. 아카이브란 무엇인가

**코드는 남기되 제품 기능으로 세지 않는 것**입니다
([D-03](../00-index/마스터인덱스.md#2-지금-확정된-설계-결정) 의 5단계 중 3번째).

| | 폐기 (X) | **아카이브 (A)** | 제품 (F) |
| --- | --- | --- | --- |
| 코드 | 삭제 | **유지** | 유지 |
| 라우트 | 제거 | **유지** | 유지 |
| 사이드바 | — | **"실습" 섹션으로 분리** | 제품 메뉴 |
| 명세 깊이 | 폐기 근거만 | **존재와 사유만** | 전체 |
| 기능 수 집계 | 제외 | **제외** | 포함 |

### 0.1 왜 지우지 않는가

**의존성 부담이 없기 때문입니다.**

| 기준 | 아카이브 8개 | 폐기 5개 |
| --- | --- | --- |
| 무거운 패키지 | **없음** — `scikit-learn` 만 | `torch` · `diffusers` · `opencv` |
| 이미지 기여 | 미미 | 2.49 GB 의 대부분 |
| Vercel 500 MB 제약 | **문제 없음** | **초과 위험** ([CN-019](../00-index/변경이력.md#cn-019)) |

`scikit-learn` 은 **제품 기능도 씁니다** — F09(퀀트 파이프라인)의
`RandomForestClassifier`·`TimeSeriesSplit` (`quant.py:614~617`),
F28(백테스트 실험실)의 `HistGradientBoostingRegressor` (`backtest_lab.py:215`).
**즉 이 8개를 지워도 의존성이 줄지 않습니다.** 지울 이유가 없습니다.

### 0.2 왜 제품 기능으로 세지 않는가

| 근거 | 내용 |
| --- | --- |
| 1 | 입력이 **실제 시장 데이터가 아니라 합성 더미**다 (`make_classification` 류) |
| 2 | 포트폴리오 분석과 **무관**하다 |
| 3 | 강사님 요구 R-01~R-08 중 어느 것에도 대응하지 않는다 |

## 2. 공통 특징

### 2.1 전부 합성 데이터입니다

여덟 기능 모두 sklearn 의 데이터 생성기나 난수로 입력을 만듭니다.
**실제 시장 데이터를 받는 경로가 없습니다.**

### 2.2 전부 PNG 한 장을 돌려줍니다

응답 필드명이 `image_base64` 이고 **`data:image/png;base64,` 접두사가 없습니다**
(`ml.py:210,317,373,424,478`). 제품 기능(`image` · 접두사 포함)과 다릅니다
→ [CN-033](../00-index/변경이력.md#cn-033).

**우선순위는 낮습니다.** 아카이브라 통일 대상에서 뒤로 뺍니다.

### 2.3 화면이 전부 작습니다

8개 합계 **약 16 KB** 입니다. 제품 화면 하나(`valuation.js` 52.6 KB)보다 작습니다.
유지 부담이 거의 없다는 뜻이기도 합니다.

## 3. v2.0 에서 하는 일

| # | 조치 | 근거 |
| --- | --- | --- |
| 1 | **사이드바에 "실습" 섹션을 만들어 8개를 모은다** | 지금은 링크가 없어 주소를 직접 쳐야 함 ([CN-018](../00-index/변경이력.md#cn-018)) |
| 2 | 화면 상단에 **"수업 실습 · 합성 데이터"** 배지 | 제품 기능과 섞이지 않게 |
| 3 | Swagger 태그를 `실습` 으로 분리 | `openapi_docs.py` |
| 4 | **그 밖에는 손대지 않는다** | 동작하고 있고 비용이 없다 |

### 3.1 하지 않는 것

- 코드 리팩터링
- 에러 처리 표준화 ([CN-036](../00-index/변경이력.md#cn-036) 적용 대상에서 제외)
- 테스트 작성 (R-06 4단계 테스트의 대상이 아님)
- 필드명 통일 ([CN-033](../00-index/변경이력.md#cn-033) 우선순위 최하)

**이유는 하나입니다** — 아카이브에 시간을 쓰면 A등급 기능에 쓸 시간이 줄어듭니다.
