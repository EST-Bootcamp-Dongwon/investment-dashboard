# ADR-DB-0001: vanilla JS 를 유지하고 빌드 단계를 만들지 않는다 (TypeScript 미도입 포함)

## 상태

채택됨 (2026-08-16)

## 맥락

이 모듈의 프론트엔드는 `app/frontend/` 아래 **번들러 없는 ES 모듈**이다. HTML 진입점이
셋이고(`index.html` · `pages/backtest-lab.html` · `pages/youtube.html`), 각 페이지가
`<script type="module">` 로 필요한 모듈을 직접 부른다. `package.json` 도 `node_modules/`
도 없다. 외부 라이브러리는 전부 CDN `<script>` 한 줄이거나(ApexCharts · Font Awesome ·
Pretendard) 빌드 시점에 받아 넣는 벤더링이다(`Dockerfile:18~20` 의 `mermaid.min.js`).

**이 결정이 지금 필요해진 이유는 배포와 팀 통합 두 가지다.**

1. `docs/spec/60-운영/배포-전략.md` §4.2 가 프런트엔드를 **Vercel 정적 호스팅**으로,
   `/api/*` 만 Python Function 으로 보내기로 확정했다. 빌드 산출물이 없으므로
   `app/frontend/` 폴더가 그대로 올라간다. 빌드 단계를 만드는 순간 이 배치가 깨진다.
2. 2026-09 팀 구성 이후 다른 사람의 백엔드가 이 프론트에 붙을 수 있다
   (`quant-contract/docs/contracts/api-contract.md` §1). 그때 바꿔야 하는 것이
   **HTML 한 줄**이어야 하고, 환경변수 치환·재빌드여서는 안 된다.

**근거가 외부 정책에 의존한다.** 프론트 프레임워크 금지는 이 레포의 기술 판단이 아니라
상위 제약이다 — `quant-contract/CONTEXT.md` 절대 제약 7, `AGENTS.md` "이 모듈 특화"
1번, 그리고 강사님 방침(`00-검수-프론트엔드-시각화-방침.md` §2.2). 그 정책이 바뀌면
이 ADR 의 1·2·3번은 재검토 대상이다.

## 결정

1. **vanilla JS(ES 모듈)를 유지한다.** Next.js · React · Vue · Svelte 로의 전환을
   제안하지 않는다. 이미 있는 화면을 그 위로 옮기지 않는다.
2. **TypeScript 를 도입하지 않는다.** 1번과 같은 결정의 다른 면이다 — TS 는 필연적으로
   트랜스파일 단계를 만들고, 그러면 3번이 깨진다.
3. **번들러·트랜스파일러·워크스페이스를 두지 않는다. 빌드 단계는 0 이다.**
   후보 라이브러리의 탈락 조건은 하나다 — *"CDN `<script>` 한 줄로 붙는가."*
   npm 설치나 `npx <도구> init` 이 필요하면 탈락한다.
4. **설정 주입은 `<meta>` 태그로 한다.** 환경변수 치환·`.env` 파일·빌드타임 상수를
   쓰지 않는다. 기준 URL 은 `<meta name="api-base">` 이고 **기본값은 빈 문자열**이라
   개인 배포본은 아무것도 바꾸지 않아도 동일 출처로 돈다
   (`app/frontend/js/api.js` · api-contract §8.2).
5. **타입 체크가 없다는 대가는 계약 테스트로 갚는다.** 스펙과 실제 응답을 대조하는
   검사를 두고, 프론트에서 타입으로 잡으려 하지 않는다 (api-contract §12).

**2차 출처를 쓰지 않았다.** 프레임워크 성능·생산성 비교 글을 인용하지 않은 이유는,
이 결정이 성능 비교로 뒤집힐 수 있는 결정이 아니기 때문이다 — 위 1번이 그것을 막는다.

## 결과

**쉬워지는 것**

- 배포가 파일 복사다. 빌드 실패라는 상태가 존재하지 않는다.
- 팀원이 붙을 때 `npm install` 이 필요 없다. HTML 한 줄이면 된다.
- 브라우저에서 보는 것과 저장소에 있는 것이 같은 파일이다. 소스맵이 필요 없다.

**어려워지는 것**

- **타입 오류를 컴파일 시점에 못 잡는다.** 백엔드 응답 필드명이 바뀌면 화면이 조용히
  `undefined` 를 그린다. 그래서 결정 5번(계약 테스트)이 이 ADR 의 일부다.
- **자산 캐시 무효화를 손으로 한다.** 지금은 `?v=` 를 손으로 올리고 있고, 실제로
  `styles.css` 버전이 세 HTML 에서 어긋나 있다(배포-전략 §4.4 실측: `v=13` / `v=10` /
  `v=10`). 지금은 `no_cache_static_assets` 미들웨어가 `no-store` 를 강제해 무해하지만,
  **정적 자산을 CDN 으로 옮기면 그 미들웨어가 경로에서 빠지고 버그가 실제로 난다.**
  이 ADR 은 그 문제를 해결하지 않는다 — 배포-전략 §4.4 의 파일명 해시 방침이 맡는다.
- **모듈 그래프를 도구가 아니라 사람이 안다.** 그래서 `js/api.js` 밖의 `fetch(` 를
  금지하는 검사를 `scripts/check_layers.py` 에 두었다. 규칙은 강제되지 않으면
  지켜지지 않는다.
