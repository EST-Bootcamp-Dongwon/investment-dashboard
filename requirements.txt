# ─────────────────────────────────────────────────────────────────────────────
# ## 왜 나뉘었나 — 500 MB
#
# Vercel Hobby 의 Python 함수 크기 상한은 **압축 해제 500 MB** 다
# (`docs/spec/60-운영/배포-전략.md` 1.1절). 현행 한 벌로는 1,649 MB 였다.
#
# ## 배포-전략 3.4절의 산수에 틀린 전제가 있었다 (2026-08-17 실측)
#
# 그 절은 *"matplotlib 을 뺀다"* 로 429.8 MB 를 계산했다. **matplotlib 줄을 지우는
# 것으로는 matplotlib 이 빠지지 않는다.**
#
#     $ pip show pykrx
#     Requires: deprecated, matplotlib, multipledispatch, numpy, pandas, requests
#
# `pykrx==1.2.8` 이 matplotlib 을 **하드 의존**한다. 그래서 matplotlib 줄만 지운
# 조합은 실측 **543 MB (108.6 %)** 로 여전히 초과였다. 지렛대는 matplotlib 줄이
# 아니라 **`pykrx`** 였다.
#
# 세 조합을 clean venv 로 실측했다 (pip·setuptools·wheel 제외한 site-packages):
#
#     ③ pykrx 제거 (matplotlib 이 딸려 나감) ·  sklearn 유지  →  426 MB  ( 85.2 %) ✅ 채택
#     ④ sklearn 제거 (scipy 가 딸려 나감)   ·  pykrx  유지  →  336 MB  ( 67.2 %)
#     ⑤ 둘 다 제거                                          →  231 MB  ( 46.2 %)
#
# ③ 을 고른 근거는 배포-전략 3.4절 그대로다 — ④ 는 **대체 수단이 없는** F28 백테스트
# 실험실을 통째로 잃고, ③ 이 잃는 것은 **렌더링 위치**와 시가총액 보강 하나다.
#
# **이 파일 그대로의 최종 실측은 432 MB (86.4 %)** 다(2026-08-17). ③ 의 426 MB 와
# 6 MB 차이 나는 것은 아래 `pandas` 핀 때문이다. 여기에 애플리케이션 코드
# (`app/backend/` 1 MB) · `docs/*.md`(360 KB) · `lean-hyundai/` 3파일이 더해진다.
# 배포-전략 8절 1번의 **(확인 필요)** 중 site-packages 몫은 이것으로 닫힌다 —
# Vercel 런타임 자체가 차지하는 몫은 첫 배포 로그에서 확인해야 한다.
#
# ## 그래서 무엇을 잃는가
#
# | 잃는 것 | 대응 |
# | --- | --- |
# | 서버 렌더 차트 16곳 | `charting.require_matplotlib()` 이 **503 + 안내 문구**를 낸다. ApexCharts 이전이 끝나는 화면부터 되살아난다 (ADR-DB-0002) |
# | `pykrx` 시가총액 보강 (group-network) | `services/dart.py:107` 이 원래부터 `try/except` 로 `{}` 를 돌려준다. 화면은 시가총액 칸만 빈다 |
